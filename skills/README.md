# Навыки BalukNotes

Навыки Claude Code, которые ставятся вместе с программой: `tools/install.sh`
кладёт каждый в `~/.claude/skills/<имя>` одной версией с `notes`. Этот файл —
принципы, по которым пишется любой навык; сам он не устанавливается.

| Навык | Что делает |
|---|---|
| `baluk-note/` | `/baluk-note`: новая заметка или книга, глава, правка, переименование |

## Для кого пишем

- **Читатель — модель.** В основном сильные (Sonnet, Opus); слабые тоже должны
  справляться, их контекст — от ~64k токенов. Поэтому правила даются **с
  причинами** (сильная модель по причине решает непредусмотренный случай), а
  образцы и справочник страхуют слабую.
- **Жёстко — только процесс**: пути, команды, проверка, шапка файла, границы
  (что можно трогать). В содержании — свобода: образец — отправная точка, а не
  предел; можно сочетать возможности и рисовать своё.
- Тон спокойный: без NEVER, капса и лишних выделений — у новых моделей они
  вызывают перестраховку (лишние вопросы, отказ от разумной инициативы).

## Самодостаточность

- Навык вызывают **из любой папки** — обычно из той, где лежат исходники
  (лекции, задачи), а не из репозитория. Всё нужное — в каталоге навыка:
  `SKILL.md` + образцы + справочник. Исходники BalukNotes и документация в
  сети модели не нужны, и навык прямо это говорит.
- Работа — только через **публичную команду `notes`** и правку файлов
  заметок. Не хватает возможности — сначала команда в CLI, потом навык.
- `allowed-tools` — только нужные команды `notes` и чтение файлов.

## Данные пользователя

- Хранилище — собственные записи пользователя. Навык работает **только в
  выбранном хранилище**, остальные не трогает. Хранилища по умолчанию нет:
  не назвал — спросить (даже если хранилище одно); сам навык хранилищ не
  создаёт.
- Создаётся и меняется только то, о чём задача. Увидел повод поменять
  что-то ещё (ссылку в другой заметке, опечатку) — сначала спросить.
- Исходники пользователя — только читать; в их папках ничего не создавать.
  Временные файлы (PDF, снимки) — во временной папке сессии.

## Язык и оформление

- Тексты для модели (`SKILL.md`, справочник, образцы) — **по-английски**: так
  меньше токенов и меньше двусмысленности.
- В начале и в конце `SKILL.md` — пункт о языке: ответ и заметка — на языке
  запроса пользователя; при правке — язык самой заметки. Отдельно сказано,
  что русский запрос — русская заметка, хотя инструкции английские.
- Сообщения `notes` (пока по-русски, перевод — в `docs/roadmap.md`) цитировать
  **дословно**: модель ищет их в выводе.
- **Простой Markdown**, без типографики: `"`, `-`, `->`, `...` вместо
  «», —, →, …. Заголовки, списки, блоки кода; таблицы — где без них хуже.
- Для людей в навыке — только `argument-hint` (подсказка в интерфейсе), он
  по-русски.

## Токены

- Размер меряем `tiktoken` (`o200k_base`) до и после правки — приблизительно
  (у Claude свой токенизатор), но быстро и локально:

  ```sh
  python3 -c 'import sys, tiktoken; e = tiktoken.get_encoding("o200k_base"); [print(len(e.encode(open(f).read())), f) for f in sys.argv[1:]]' skills/baluk-note/SKILL.md
  ```

- Без воды и повторов, но **причины правил и полнота важнее экономии**.
- Число токенов в тексте навыка не писать: модели оно ни к чему и устареет.
- Большое и не всегда нужное — в отдельный файл, который `SKILL.md` велит
  прочитать, когда он нужен (справочник, образцы).

## Устройство навыка

```
<имя>/
  SKILL.md       порядок работы, правила с причинами, частые ошибки
  reference.md   полные сигнатуры и допустимые значения (если есть API)
  examples/      образцы: целые файлы, которые собираются без ошибок
```

`SKILL.md`:
- шапка: `name`, `description` (по-английски), `disable-model-invocation:
  true` (навык зовёт пользователь), `argument-hint`, `allowed-tools`;
- просьба пользователя — подстановкой `$ARGUMENTS`, в начале и ещё раз в
  конце (длинный промпт: задача не теряется). `$` с цифрой не писать:
  оболочка заменит `$0` словом из вызова;
- дальше: язык → контекст (что это за программа и где результат) → выбор
  задачи → шаги по порядку → справка (пути, синтаксис, ошибки CLI) →
  правила качества → частые вызовы → указатель образцов.

Образцы:
- вместе используют **каждое** публичное имя библиотеки;
- у вызовов — комментарии: что делает и зачем, а не перечень параметров
  (он — в справочнике);
- читаются целиком перед планом: модель должна знать, что умеет
  библиотека, до того как предлагать рисунки.

## Проверка

Навык проверяется вместе с проектом (`tools/check.sh --rust`):

- шаг `baluk-note`: заготовки `notes new`, все образцы и блок «Common calls»
  из `SKILL.md` собираются во временном хранилище без ошибок,
  предупреждений и битых ссылок;
- `cargo test -p notes-core --test library`: вызовы `#имя` в `SKILL.md` —
  публичные имена библиотеки; каждое имя есть в образцах; справочник
  совпадает с исходниками по именованным параметрам и значениям по
  умолчанию; есть `$ARGUMENTS` и нет `$цифра`.

Поменял библиотеку, шаблоны `note`/`book`, команды `notes` или правила путей —
поправь в том же изменении `SKILL.md`, образцы, справочник и
`docs/writing.md`, затем `tools/install.sh`.

## Новый навык

1. Каталог `skills/<имя>/` с `SKILL.md` по разделам выше.
2. Установка — в `tools/install.sh` (целиком заменить копией, как
   `baluk-note`).
3. Проверка сборки его образцов — шаг в `tools/check.sh`, проверки текста —
   тест рядом с `library.rs`.
4. Строка в таблицу выше и в `README.md` проекта.
