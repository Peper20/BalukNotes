# Как писать заметки

Правила **содержания** заметок BalukNotes: что писать и как проверять
(`notes docs writing`). Вёрстку делает библиотека `baluk`, её API -
`notes docs library`. Новую заметку заводит навык Claude Code `/baluk-note`;
всё - через команду `notes`, из любой папки:

| Команда | Что делает |
|---|---|
| `notes vaults`, `notes vaults new "Имя"` | хранилища; новое хранилище |
| `notes new --vault "Имя" --title "Название" [--folder Папка] [--book] [--tag ...] [--lang ...]` | заготовка заметки или книги, имя файла - из названия; печатает путь файла и путь заметки |
| `notes list --vault "Имя"`, `notes tags --vault "Имя"` | заметки (путь, книга, название, теги) и теги |
| `notes check --vault "Имя" [Путь]` | ошибки сборки, предупреждения, битые ссылки |
| `notes pdf --vault "Имя" Путь -o файл.pdf [--theme night]` | PDF заметки или книги |
| `notes info [--vault "Имя"]` | где хранилища, адрес приложения |
| `notes serve` | приложение: `http://127.0.0.1:8421/v/<Хранилище>/n/<Путь>`; в фоне и при входе в систему - `notes service install` |

Хранилища по умолчанию нет: командам заметок всегда нужен `--vault "Имя"`
(список - `notes vaults`); первое хранилище создаёт пользователь.

## Главное

Заметка **объясняет**, а не перечисляет: читатель хочет понять тему с нуля и
потом решать задачи. Читает он в приложении - с компьютера или телефона, в
светлой или тёмной теме, по главе за раз; PDF - тот же текст для печати.

- Сначала "зачем", потом "что", потом "как пользоваться".
- Определение и теорема обязательны, но понимание дают рисунок и разобранный
  пример рядом.
- Трудное - подробнее лёгкого; равномерно сжатый текст - провал.
- Плотный справочник (таблицы "конструкция -> смысл", стены кода) - это
  шпаргалка, отдельная заметка (`book.with(kind: [Шпаргалка], ...)`).

## Заметка или книга

| Вид | Что это | Файл |
|---|---|---|
| **Заметка** (`note`) | одна тема: определение, приём, инструмент, задача; `=` - раздел, нумерация сквозная | `Папка/Имя.typ` |
| **Книга** (`book`) | курс или большая тема: `=` - глава, нумерация "глава.n", титул и оглавление в PDF | `Папка/Имя/main.typ` + главы `NN-тема.typ` |

**Название и путь - разное.** Название - `title: [...]` в файле (у книги - в
`main.typ`), любые знаки; его показывают дерево, вкладки, граф и ссылки
(формула там - исходником: `[Ряд $sum 1/n^2$]` -> "Ряд sum 1/n^2", лучше
словами). Путь -
где лежит файл (`Сеть/SSH основы`): по нему ссылаются (`#see`), проверяют и
собирают PDF. `notes new --title` берёт имя файла из названия (без
`/ \ : * ? " < > |`, занятое - с номером) и печатает путь второй строкой.
Переименовать - `notes rename --vault "Имя" Путь "Новое название"` (или в
приложении: правый клик в дереве -> "Переименовать..."): меняются название,
имя файла (папки) в той же папке, а ссылки `#see` на неё в других заметках
переписываются; `--dry-run` - только показать. Только название, без имени
файла, - поправить `title:`. Название папки - `_folder.toml` в ней: `title =
"Сети и протоколы"` (нет файла - имя папки).

- Короткие заметки на одну мысль связываются ссылками, как в Obsidian:
  `#see("Математика/Производная")`, раздел - `anchor: "Заголовок"`. Из ссылок
  строятся "Ссылаются сюда" и граф. Ссылка на ненаписанную заметку - битая:
  написать заметку или не ссылаться.
- Теги - `tags: ("матан", "интегралы")`: строчные, по-русски, общие для
  хранилища (существующие - `notes tags`).
- **Характеристики книги и глав.** `main.typ` - корень книги: `book.with(...)`
  задаёт общее для всех глав (язык, слова, теги темы целиком), глава его
  наследует. Своё у главы, как у заметки, - `#show: chapter.with(title: [...],
  tags: (...))` в начале её файла вместо `= Название`: название и свои теги
  (добавляются к тегам книги; видны под заголовком главы и на странице тега).
  Первая глава - обычная глава: общее книги - только в корне.
- Язык - `lang:` (по умолчанию `"ru"`); для языков кроме `ru` и `en` - свои
  `words:`.

## Процесс

1. Выяснить **цель** (экзамен, контест, лаба, "разобраться") и **читателя**:
   что он знает уверенно, а что плохо (плохо знакомому - больше места).
   Собрать исходники: лекции, задачи, прошлые билеты - часто они в папке, из
   которой вызван навык. Исходники и оригиналы конспектов
   (`~/Documents/abstract/...`) только читать; всё своё - в хранилище,
   черновики и снимки - во временной папке.
2. Согласовать **план** до текста: для книги - главы и разделы, для заметки -
   разделы; для каждой - рисунки, примеры, трудные места. Дождаться "да".
3. Писать по главе (разделу); после каждой - проверка (ниже) и запись в
   **шапке** файла - комментарии `//` в начале `main.typ` книги или заметки:
   цель и читатель, исходники, план, что сделано, что дальше. Шапку пишет
   автор (`notes new` её не создаёт). Работа часто прерывается - следующая
   сессия начинает с шапки. Готово - шапку удалить.
4. Визуализации добавлять сразу, не дожидаясь просьбы.

Пользователь видит заметку по мере написания: `notes serve` подхватывает
правки сам.

## Глава книги (раздел заметки - так же, без `plan`)

```typst
#import "/_baluk/lib.typ": *

= Название главы              // или #show: chapter.with(title: [...], tags: (...))
#lead[2-4 предложения: зачем глава и на что опирается]
#plan([что научимся делать], [...], [...])

== Раздел                    // мотивация -> интуиция с рисунком -> строгость
   #definition / #theorem    коротко
   #example                  по шагам: #step[Рисунок] ... #step[Пределы] ... #answer[...]
   #pitfall                  главная ловушка раздела, сразу после примера

#pitfalls(...)   #summary(...)   #quiz(...)      // в конце главы
```

- Глава в PDF начинается с новой страницы, в приложении показывается отдельно,
  поэтому короткая тема - **раздел**. Ориентир: глава от 3 страниц PDF.
- На каждое определение и теорему - хотя бы один разобранный пример.
- Ссылки внутри заметки: `рис. @метка`, `в разделе @sec-x` (падежное слово -
  руками). На другую заметку - только `#see`.

## Текст

- Живой язык от первого лица множественного числа: "разобьём", "заметим".
- Новый термин - `*жирным*`, объяснение сразу рядом.
- Голых формул не бывает: перед - что она говорит, после - как ею
  пользоваться. Ключевая формула раздела - `#formula[...]`, одна-две на раздел.
- Трудное место: 2-3 примера от простого к сложному, трассировка по шагам,
  `#proof`, типичная ошибка.
- Врезки (`remark`, `idea`, `pitfall`, `margin-note`) - приправа: не больше
  одной на полстраницы.
- `$dc("0,5")$`, а не `$0,5$` (напечатается "0, 5"). Операторы русские: `tg`,
  `ctg`, `sh`, `ch`.
- `;` сразу после `#вызова(...)` Typst съедает - писать `\;` (`notes check`
  предупреждает).
- Кегль, шрифты и цвета - только из темы: заметка не задаёт `set text(size:
  ...)` и `rgb(...)`. Ужимать, чтобы влезло, нельзя.

## HTML - главный вид

Один исходник даёт страницу и PDF, но читают в основном страницу.

- **Раскладка - только блоками библиотеки**: `side-by-side` (текст и рисунок
  рядом), `in-row` (рисунки в ряд), `fig`, `data-table`. В HTML Typst
  выбрасывает `grid`, `stack`, `align`, `place`, а `h`/`v` с `fr` и
  процентами пропадают. Нужна новая раскладка - это правка библиотеки:
  сказать пользователю.
- Своего HTML, JS и стилей у заметки нет (`html.elem` не писать): интерактив -
  только блоками библиотеки.
- Свои линии и заливки - цветами темы (`theme.color.fig.second`,
  `pale(theme, color)`), иначе в тёмной теме `night` их не видно.

Пакеты Typst - только из белого списка (CeTZ библиотеки берёт сама); другой -
ошибка сборки, разрешить его может только пользователь в настройках
устройства ("Пакеты Typst сверх белого списка").

## Рисунки - обязательно, без напоминаний

Норма: 2-3 рисунка на главу и хотя бы один в каждом разделе про геометрию,
структуру данных, алгоритм или схему - рядом с объясняющим текстом и со
ссылкой из него.

- **Подпись - утверждение, а не название.** Плохо: "Область D". Хорошо:
  "Спица входит в D через параболу и выходит через прямую - это пределы
  внутреннего интеграла".
- Алгоритм - **кадрами** (`frames`): в приложении ползунок и проигрывание, в
  PDF кадр по умолчанию или раскадровка `pdf: (1, 4, 8)`. Один статичный
  рисунок для алгоритма - мало.
- Зависимость от параметра - `interactive-plot` (ползунки) или
  `interactive-surface` (3D с вращением).
- Выделение - одним цветом темы (`"second"`), не радугой; подписи не мельче
  8pt.
- Крупный рисунок - `fig(..., floating: true)` (в PDF - вверх или вниз
  страницы), маленький к абзацу - `side-by-side`.
- Что есть в библиотеке, не рисовать заново: оси, графики, 3D, массивы,
  матрицы, графы, деревья, диаграммы, граф хранилища. Сверх этого - свои
  рисунки на CeTZ в `canvas(theme => ...)` цветами темы (линии, многоугольники,
  подписи, точки `p3`, свои помощники). Нужен новый **вид** рисунка или
  раскладки, полезный и другим заметкам, - нарисовать пока в заметке и сказать
  пользователю.

| Предмет | Обязательные картинки |
|---|---|
| Математический анализ | спицы для пределов, графики, 3D-поверхность, тела и сечения, интегральные суммы (кадрами) |
| Алгоритмы и структуры данных | массив с блоками, сводами, указателями и дугами; кадры работы; граф с текущим шагом; таблица ДП со стрелками |
| Базы данных | данные **до** запроса и **результат**; какие строки совпали при соединении; рамка окна |
| Архитектура ЭВМ | блок-схема, иерархия памяти, конвейер по тактам, разбиение адреса на поля |
| Теория вероятностей | геометрическая вероятность, деревья исходов, плотность и функция распределения |
| Любой предмет | измерения и сравнения - `chart`, а не таблица чисел |

## Код

- Идёт **после** объяснения идеи и не заменяет её; два листинга подряд без
  текста между ними нельзя.
- `listing` до 25 строк, ключевые строки - `highlight:` и `callouts:`, в тексте
  "строка #callout(1) - ..."; рядом сложность (`complexity:`) и пример входа и
  выхода.
- Рабочий код лежит рядом с книгой (`Папка/Книга/code/...`), компилируется и
  тестируется (случайные тесты против наивного решения); в главу берётся
  регион: `#code-from-file("/Папка/Книга/code/x.cpp", region: "build")` - путь
  от корня хранилища.
- **SQL: у каждого запроса - результат** (первые 3-5 строк таблицей).

## Проверка (после каждой главы или раздела)

```sh
notes check --vault "Имя" "Папка/Книга"              # ошибки, предупреждения ("0,5" в формуле, ;), битые ссылки
notes pdf --vault "Имя" "Папка/Книга" -o $TMP/k.pdf  # и --theme night -o $TMP/k-night.pdf
pdftoppm -r 70 -png $TMP/k.pdf $TMP/стр              # и ПОСМОТРЕТЬ страницы (PNG)
```

- `$TMP` - временная папка, не хранилище и не папка с исходниками.
- Страница - `http://127.0.0.1:8421/v/<Хранилище>/n/Папка/Книга` в браузере
  (Claude in Chrome): светлая и тёмная тема (переключатель вверху справа),
  узкое окно (~400 px), интерактив. Сервер не запущен - `notes serve` (или
  попросить пользователя; насовсем - `notes service install`).
- У своей заметки - ни ошибок, ни предупреждений, ни битых ссылок; чужие
  проблемы хранилища (`notes check` без пути) не чинить молча - сказать
  пользователю.
- Каждое число пересчитано независимо (Python, sympy, перебор, симуляция);
  подпись рисунка сверена с координатами самого рисунка.
- Глазами: наложения подписей, перепутанная ось y, невидимые в темноте линии,
  висячие заголовки, "0, 5" вместо "0,5", код за правым краем, таблица шире
  экрана телефона.

## Чек-лист главы

- [ ] лид и план; в каждом разделе мотивация, рисунок, пример по шагам
- [ ] трудные места разобраны подробнее лёгких
- [ ] 2-3 рисунка и больше, у каждого подпись-утверждение и ссылка из текста
- [ ] алгоритмы - кадрами, SQL - с результатами
- [ ] листинги до 25 строк, код скомпилирован и протестирован
- [ ] числа пересчитаны независимо
- [ ] `pitfalls`, `summary`, `quiz` в конце
- [ ] `notes check` чистый; PDF и страница (светлая, тёмная, узкий экран)
      просмотрены
- [ ] шапка файла отражает, что сделано и что дальше
