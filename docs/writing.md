# Как писать заметки

Правила **содержания** заметок BalukNotes: что писать и как проверять
(`notes docs writing`). Вёрстку делает библиотека оформления `baluk` — её
API: `notes docs library`. Новую заметку заводит навык Claude Code
`/baluk-note`; всё — через команду `notes`, из любой папки:

| Команда | Что делает |
|---|---|
| `notes vaults`, `notes vaults new "Имя"` | хранилища; новое хранилище |
| `notes new --vault "Имя" --title "Название" [--folder Папка] [--book] [--tag …] [--lang …]` | заготовка заметки или книги, имя файла — из названия; печатает путь файла и путь заметки |
| `notes list --vault "Имя"`, `notes tags --vault "Имя"` | заметки хранилища (путь, книга, название, теги) и теги |
| `notes check --vault "Имя" [Путь]` | ошибки сборки, предупреждения, битые ссылки |
| `notes pdf --vault "Имя" Путь -o файл.pdf [--theme night]` | PDF заметки или книги |
| `notes info [--vault "Имя"]` | где хранилища (и папка хранилища), адрес приложения |
| `notes serve` | приложение: `http://127.0.0.1:8421/v/<Хранилище>/n/<Путь>` |

Хранилища по умолчанию нет: командам заметок всегда нужен `--vault "Имя"`
(список — `notes vaults`); первое хранилище создаёт пользователь.

## Главное

Заметка **объясняет**, а не перечисляет: читатель хочет понять тему с нуля
и потом решать задачи. Читает он в приложении — с экрана компьютера или
телефона, в светлой или тёмной теме, по главе за раз; PDF — тот же текст
для печати.

- Сначала «зачем», потом «что», потом «как пользоваться».
- Определение и формулировка теоремы обязательны, но понимание дают
  рисунок и разобранный пример рядом с ними.
- Трудное — подробнее лёгкого; равномерно сжатый текст — провал.
- Плотный справочник (таблицы «конструкция → смысл», стены кода) — это
  шпаргалка, отдельная заметка (`book.with(kind: [Шпаргалка], …)`), а не
  конспект.

## Заметка или книга

| Вид | Что это | Файл |
|---|---|---|
| **Заметка** (`note`) | одна тема: определение, приём, инструмент, задача; `=` — раздел, нумерация сквозная | `Папка/Имя.typ` |
| **Книга** (`book`) | курс или большая тема: `=` — глава «Глава N», нумерация «глава.n», титул и оглавление в PDF | `Папка/Имя/main.typ` + главы `NN-тема.typ` |

**Название и путь — разные вещи.** Название — `title: […]` в самом файле
(у книги — в `main.typ`): в нём можно любые знаки, его показывают дерево,
вкладки, граф и ссылки. Путь — где файл лежит (`Сеть/SSH основы`): по нему
ссылаются (`#see`), проверяют и собирают PDF. `notes new --title` берёт имя
файла из названия (без `/ \ : * ? " < > |`, занятое — с номером) и печатает
путь второй строкой. Переименовать заметку — поправить `title:`; ссылки без
своей подписи покажут новое название сами. Название папки — файл
`_folder.toml` в ней: `title = "Сети и протоколы"` (нет файла — имя папки).

- Короткие заметки на одну мысль связываются ссылками, как в Obsidian:
  `#see("Математика/Производная")`, раздел — `anchor: "Заголовок"`. Из
  ссылок приложение строит «Ссылаются сюда» и граф. Ссылка на
  ненаписанную заметку — битая (`notes check`): либо написать заметку,
  либо не ссылаться.
- Теги — `tags: ("матан", "интегралы")`: строчными, по-русски, общие для
  хранилища (уже существующие — в приложении, Ctrl+K → «Теги»).
- Язык — `lang:` (по умолчанию `"ru"`); слова оформления для `ru` и `en`
  есть, для другого языка — свои `words:`.

## Процесс

1. Выяснить **цель** (экзамен, контест, лаба, «разобраться») и **читателя**
   — что он знает уверенно, а что плохо; плохо знакомому — больше места.
   Собрать исходники: лекции, задачи, прошлые билеты — часто они лежат в
   папке, из которой вызван навык. Исходники и оригиналы конспектов
   (`~/Documents/abstract/…`) только читать, никогда не менять; всё своё —
   в хранилище, черновики и снимки — во временной папке.
2. Согласовать **план** до текста: для книги — главы → разделы, для
   заметки — разделы; для каждой главы (раздела) — рисунки, примеры,
   трудные места. Дождаться «да».
3. Писать по одной главе (разделу); после каждой — проверка (ниже) и
   запись в **шапке** файла (`main.typ` книги или сама заметка): цель и
   читатель, исходники, план, что сделано, что дальше. Работа часто
   прерывается — следующая сессия начинает с шапки. Готово — шапку удалить.
4. Визуализации добавлять сразу, не дожидаясь просьбы.

Пользователь видит заметку в приложении по мере написания: `notes serve`
подхватывает правки файла сам (`http://127.0.0.1:8421/n/<Путь>`).

## Глава книги (раздел заметки — так же, без `plan`)

```typst
#import "/_baluk/lib.typ": *

= Название главы
#lead[2–4 предложения: зачем глава и на что опирается]
#plan([что научимся делать], [...], [...])

== Раздел                    ← мотивация → интуиция с рисунком → строгость
   #definition / #theorem    коротко
   #example                  по шагам: #step[Рисунок] … #step[Пределы] … #answer[…]
   #pitfall                  главная ловушка раздела, сразу после примера

#pitfalls(...)   #summary(...)   #quiz(...)      ← в конце главы
```

- Глава в PDF начинается с новой страницы, в приложении показывается
  отдельно, поэтому короткая тема — **раздел**. Ориентир: глава ≥ 3
  страниц PDF.
- На каждое определение и теорему — минимум один разобранный пример.
- Ссылки внутри заметки: `рис. @метка`, `в разделе @sec-x` — падежное
  слово пишется руками. На другую заметку — только `#see`.

## Текст

- Живой язык от первого лица множественного числа: «разобьём», «заметим».
- Новый термин — `*жирным*`, объяснение сразу рядом.
- Голых формул не бывает: перед — что она говорит, после — как ею
  пользоваться. Ключевая формула раздела — `#formula[…]`, одна-две на раздел.
- Трудное место: 2–3 примера от простого к сложному, трассировка по шагам,
  `#proof`, типичная ошибка.
- Врезки (`remark`, `idea`, `pitfall`, `margin-note`) — приправа: не больше
  одной на полстраницы.
- `$dc("0,5")$`, **не** `$0,5$` (напечатается «0, 5»). Операторы русские:
  `tg`, `ctg`, `sh`, `ch` (`notes docs library`, «Математика»).
- `;` сразу после `#вызова(…)` Typst съедает — писать `\;` (`notes check`
  предупреждает).
- Кегль, шрифты и цвета — только из темы: заметка не задаёт `set text(size:
  …)`, цвета — `rgb(…)`. Ужимать, чтобы «влезло», нельзя.

## HTML — главный вид

Один исходник даёт страницу в приложении и PDF, но читают в основном
страницу.

- **Раскладку — только блоками библиотеки**: `side-by-side` (текст и
  рисунок рядом), `in-row` (рисунки в ряд), `fig`, `data-table`. В
  HTML-экспорте Typst `grid`, `stack`, `align`, `place` выбрасываются, а
  `h`/`v` с `fr` и процентами пропадают; шаблон страхует, но вид будет не
  тот. Нужна новая раскладка — это правка библиотеки, а не заметки:
  сказать пользователю (библиотеку правят отдельно, в репозитории
  BalukNotes).
- Своего HTML, JS и стилей у заметки нет (`html.elem` в заметке не писать):
  интерактив — только блоками библиотеки.
- Рисунки проверять и в тёмной теме `night`: свои линии и заливки — цветами
  темы (`theme.color.fig.second`, `pale(theme, color)`), иначе в темноте
  их не видно.

## Рисунки — обязательно, без напоминаний

Норма: 2–3 рисунка на главу и хотя бы один в каждом разделе про геометрию,
структуру данных, алгоритм или схему, рядом с объясняющим текстом и со
ссылкой из него.

- **Подпись — утверждение, а не название.** Плохо: «Область D». Хорошо:
  «Спица входит в D через параболу и выходит через прямую — это пределы
  внутреннего интеграла».
- Алгоритм показывается **кадрами**: `frames` — в приложении ползунок и
  проигрывание, в PDF кадр по умолчанию или раскадровка `pdf: (1, 4, 8)`.
  Один статичный рисунок для алгоритма — мало.
- Зависимость от параметра — `interactive-plot` (ползунки) или
  `interactive-surface` (3D с вращением); в PDF — кадр при значениях по
  умолчанию.
- Выделение — одним цветом темы (`"second"`), не радугой; подписи не мельче
  8pt.
- Крупный рисунок — `fig(…, floating: true)` (в PDF встанет вверх или низ
  страницы), маленький к абзацу — `side-by-side`.
- Ничего не изобретать заново: оси, графики, 3D, массивы, матрицы, графы,
  деревья, диаграммы по данным, граф хранилища уже есть
  (`notes docs library`). Не хватает инструмента — это правка
  **библиотеки**: сказать пользователю, а не рисовать своё в заметке.

| Предмет | Обязательные картинки |
|---|---|
| Математический анализ | спицы для пределов, графики, 3D-поверхность, тела и сечения, интегральные суммы (кадрами) |
| Алгоритмы и структуры данных | массив с блоками, сводами, указателями и дугами; кадры работы; граф с текущим шагом; таблица ДП со стрелками |
| Базы данных | данные **до** запроса и **результат**; какие строки совпали при соединении; рамка окна |
| Архитектура ЭВМ | блок-схема, иерархия памяти, конвейер по тактам, разбиение адреса на поля |
| Теория вероятностей | геометрическая вероятность, деревья исходов, плотность и функция распределения |
| Любой предмет | измерения и сравнения — `chart`, а не таблица чисел |

## Код

- Идёт **после** объяснения идеи и не заменяет её; два листинга подряд без
  текста между ними запрещены.
- `listing` ≤ 25 строк, ключевые строки — `highlight:` и `callouts:`, в
  тексте ссылка «строка #callout(1) — …»; рядом сложность (`complexity:`) и
  пример входа/выхода.
- Рабочий код лежит в хранилище рядом с книгой (`Папка/Книга/code/…`;
  где хранилище — `notes info`), компилируется и тестируется (случайные тесты против наивного решения); в
  главу берётся регион: `#code-from-file("/Папка/Книга/code/x.cpp", region:
  "build")` — путь от корня хранилища.
- **SQL: у каждого запроса — результат** (первые 3–5 строк таблицей).

## Проверка (после каждой главы или раздела)

```sh
notes check "Папка/Книга"                          # ошибки, предупреждения (в т.ч. «0,5» в формуле, ;), битые ссылки
notes pdf "Папка/Книга" -o $TMP/k.pdf              # и --theme night -o $TMP/k-night.pdf
pdftoppm -r 70 -png $TMP/k.pdf $TMP/стр            # и ПОСМОТРЕТЬ страницы (PNG)
```

- `$TMP` — временная папка (scratchpad), не хранилище и не папка с
  исходниками.
- Страница в приложении — `http://127.0.0.1:8421/n/Папка/Книга` в браузере
  (Claude in Chrome): светлая и тёмная тема (переключатель вверху
  справа), узкое окно (~400 px), интерактив — ползунки, кадры, вращение.
  Сервер не запущен — `notes serve` (или попросить пользователя).
- У своей заметки — ни ошибок, ни предупреждений, ни битых ссылок; чужие
  проблемы хранилища (`notes check` без пути) не чинить молча — сказать
  пользователю.
- Каждое число пересчитано независимо (Python, sympy, перебор, симуляция);
  подпись рисунка проверена по координатам самого рисунка.
- Глазами — обе темы и узкий экран: наложения подписей, перепутанная ось y,
  невидимые в темноте линии, висячие заголовки, «0, 5» вместо «0,5», код за
  правым краем, таблица шире экрана телефона.

## Чек-лист главы

- [ ] лид и план; в каждом разделе мотивация, рисунок, пример по шагам
- [ ] трудные места разобраны подробнее лёгких
- [ ] ≥ 2–3 рисунка, у каждого подпись-утверждение и ссылка из текста
- [ ] алгоритмы — кадрами, SQL — с результатами
- [ ] листинги ≤ 25 строк, код скомпилирован и протестирован
- [ ] числа пересчитаны независимо
- [ ] `pitfalls`, `summary`, `quiz` в конце
- [ ] `notes check` чистый; PDF и страница (светлая, тёмная, узкий экран)
      просмотрены
- [ ] шапка файла отражает, что сделано и что дальше
