## Отрисовка

- **Обработка рисунков — разбор текста SVG** (`figures.rs`), а не дерева:
  SVG существует только как вывод `typst-svg`. Опирается на его формат (тег
  за тегом, относительные команды пути `m l h v c q a Z`). Непонятное —
  оставляется как есть, но новая версия Typst может молча выключить
  сжатие. Как закрыть: тест на число слитых рисунков в `tests/vault`
  уже есть — следить при обновлении; в идеале — свой вывод кадров.
- **Метка `data-k-figs` — хэш таблицы цветов**: две заметки на одной
  странице (вкладки M2) с одинаковой меткой не конфликтуют, с разными — тоже;
  но если тело вставлено без `<style>` из `styles`, рисунки станут без цвета.
  Клиенту — всегда вставлять `styles` вместе с `body`.
- **Каждая тема — полная компиляция** (теперь параллельно, в своём потоке):
  две темы — вдвое больше работы процессора, хотя текст одинаков. Как
  закрыть: компилировать текст один раз, а рисунки (`html.frame`) — по
  темам; нужна поддержка в Typst или своя раскладка кадров.
- **Первая сборка большой книги — секунды** («Матан» 7,4 с в релизе; почти
  всё время — рисунки CeTZ). Кэш на диске убирает её после перезапуска, но
  не после правки главы. Как закрыть: компиляция по главам с переносом
  счётчиков или кэш рисунков по их исходнику.
- **Ctrl+F и печать видят одну главу книги**: в странице только показанная
  глава (её отдаёт сервер). Поиск по всем заметкам есть (палитра, `/`), но
  браузерный поиск и печать страницы — нет. Как закрыть: печать — через PDF
  (⎙, уже есть); поиск по книге — пункт палитры «в этой книге».
- **Главы режутся по тексту HTML** (`notes-core::book`), не по дереву
  typst-html: после обработки рисунков дерева уже нет. Опирается на то, что
  `typst-html` закрывает теги и экранирует `<`; непонятное — книга
  показывается целиком. Переход в другую главу — запрос к серверу (из кэша,
  ~10 мс локально; на медленной сети — заметная пауза). Как закрыть: при
  необходимости — предзагрузка соседних глав.
- **`h`/`v` в HTML пропадают** (предупреждение «h was ignored»): горизонтальные
  и вертикальные отступы внутри текста теряются. Пока безобидно. Как закрыть:
  страховка `show h` → `span` с шириной, где величина абсолютная.
- **Скобки в формулах — эвристика.** `stretchy="false"` ставится, если между
  скобками нет дробей, корней, пределов, матриц (`render::TALL`). Высокие
  конструкции, не попавшие в список, получат нерастянутые скобки. Как
  закрыть: дополнять список по мере встречи; в идеале — исправление в Typst.
- **Изменение дерева typst-html после интроспекции** (typst#7951): ссылки
  внутри перенесённых вариантов рисунков разрешаются по базовому документу.
  Внутри рисунков ссылок пока нет.
- **Слаг якоря выбрасывает знаки:** «C++ и сборка» → `C-и-сборка`, два
  заголовка «C» и «C++» получат `C` и `C-2`. Как закрыть: транслитерация
  знаков (`+` → `plus`) или id по метке.

## Библиотека `baluk`

- **Словари оформления — только `ru` и `en`** (`i18n.typ`), и добавить язык
  можно только правкой библиотеки; язык не из словаря молча получает русские
  слова. Сообщения об ошибках библиотеки — всегда по-русски. Как закрыть:
  параметр шаблона `words: (…)` поверх словаря; предупреждение о языке без
  словаря (`notes check`).
- **Старые имена не поддерживаются**: заметки на прежнем русском API
  (`#рис`, `холст`, `#см`…) не собираются, слоя совместимости нет. Копии в
  `data/vault` и фикстуры переведены; оригиналы конспектов вне проекта — на
  старом API, и новый импорт оттуда требует перевода. Решено (2026-09-26):
  переводчик старого API не храним — импорт заменит новый инструмент на
  основе BalukNotes.
- **Префикс `k-` в классах, CSS-переменных и `data-k-*`**, `K_THEMES` в
  статическом сайте — наследие прежнего имени библиотеки. Вреда нет, но имя
  не говорит о проекте. Пользователь (2026-09-26): оставить. Если понадобится —
  переименовать разом (ядро, CSS, клиент, снимки).

## Шрифты

- **Математический шрифт не режется** (New Computer Modern Math, CFF с
  таблицей `MATH`): `fontcull` не умеет ни CFF, ни замыкание `MATH`, а без
  него пропали бы растягиваемые скобки. Отдаётся целиком в WOFF2 — 0,66 МБ,
  теперь это самый тяжёлый файл страницы. Как закрыть: подмножество с
  `MATH` (когда появится в fontations/klippa) или TrueType-версия шрифта.
- **Части шрифта — по наборам знаков, а не по знакам страницы**: латиница
  грузится целиком (~40 КБ), даже если на странице три латинские буквы.
  Кернинг между знаками из разных частей теряется (кавычки «» из латиницы
  рядом с кириллицей). Как закрыть: подмножество по знакам сайта при
  `notes build` — ценой пересжатия при каждой сборке.
- **WOFF2 без преобразования `glyf`** (свой простой кодировщик): файлы на ~10 %
  больше, чем у эталонного `woff2_compress`. Как закрыть: преобразование
  контуров по спецификации или крейт с ним (`ttf2woff2` — только TrueType).
- **Сжатие шрифтов — при запуске сервера** (в фоне, ~5 с процессора: brotli
  11 и подмножества ~50 частей) и заново при каждом запуске; статический
  сайт — столько же при каждой сборке. Как закрыть: кэш частей на диске
  (`data/cache`) по хэшу файла шрифта.
- **`fontcull` тянет свою копию fontations** (`fontcull-read-fonts`,
  `-skrifa`, `-klippa`): вторая копия рядом с той, что у Typst, — дольше
  сборка с нуля. Как закрыть: klippa из fontations напрямую, когда её
  опубликуют.
- **Шрифты из коллекций (`.ttc`) не раздаются.** Сейчас такие не нужны.
- **Шрифты оформления встроены в бинарник целиком** (`fonts/`, 4,6 МБ: Gentium
  Plus и JetBrains Mono, по 4 начертания) — ради одинаковой отрисовки везде.
  Файлы взяты из пакетов Debian (`fonts-sil-gentiumplus` 6.200 — сборка SIL;
  `fonts-jetbrains-mono` 2.304 — Debian собирает из исходников, возможны
  мелкие отличия от релиза JetBrains). Чем грозит: +4,6 МБ к бинарнику;
  встроенные семейства нельзя подменить системными (только `--font-path`).
  Как закрыть: при желании — заменить файлы официальными релизами (SIL,
  GitHub JetBrains) и обновить снимки.

## Ядро и сервер

- **Прогрев уступает пользователю только между сборками**: начатую сборку
  (книга — секунды) Typst не прервёт, запрос открытой заметки её ждёт.
  Порядок ещё не собиравшихся заметок — по размеру исходников
  (приближение: время решают рисунки CeTZ); собиравшихся — по времени
  прошлой сборки из кэша. Как закрыть: отмена сборки или параллельные
  сборки (см. «Прерванная сборка»).
- **Прогрев перепроверяет хранилище раз в минуту** (`stat` всех файлов
  всех заметок): на тысячах заметок — заметная, хоть и фоновая, работа.
  Как закрыть: наблюдатель файловой системы или реже при простое.
- **Встроенная библиотека не входит в версии заметок**: у её файлов нет
  пути на диске. Вместо этого её хэш входит в метку кэша на диске
  (`LibrarySource::fingerprint`, считается при запуске): новая библиотека —
  всё собирается заново. В отладочной сборке по умолчанию берётся каталог
  `baluk/`, и правки видны. `--library` в релизе — тоже каталог.
- **Хранилище не собирается обычным `typst compile`**: `/_baluk/` есть
  только в приложении. PDF — через приложение (`notes pdf`, кнопка ⎙). Как
  закрыть, если понадобится: команда выгрузки библиотеки в хранилище.
- **PDF собирается на каждый запрос** (без кэша): «Матан» — ~2 с. Для
  одного пользователя приемлемо.
- **Компиляции идут по одной** (общий `FileStore` под мьютексом). Для одного
  пользователя неважно; для сервера на много пользователей — узкое место.
- **Нет авторизации и HTTPS.** Сервер по умолчанию слушает только 127.0.0.1.
  Есть только общий токен (`serve --token`, для Tauri): один на всех, без
  пользователей и срока. До выкладки на VPS (M5) — обязательно.
- **Токен — упрощённо** (`notes-server/src/auth.rs`): cookie без `Secure`
  (localhost по HTTP), токен из `?token=` остаётся в адресной строке и
  истории до перехода; неизвестные пути (404) отвечают и без токена.
  Клиент токен сам не шлёт — полагается на cookie (слой API с токеном — R8).
  Для Tauri достаточно; для сети — HTTPS и настоящая авторизация (M5).
- **Настройки одни на всё приложение** (`data/settings.json`), без пользователей.
- **`notes check` не проверяет ссылки заметки, которая не собралась.**
- **Индекс ссылок видит только буквальные `#see("путь")`** (разбор
  исходников, без компиляции — ради скорости). Вычисляемый путь в обратные
  ссылки и граф не попадёт; `notes check` его всё равно проверит по
  собранной странице. Как закрыть: при удачной сборке дополнять индекс
  ссылками из `Rendered.links`.
- **Индекс обходит хранилище при каждом запросе** (`stat` всех файлов, разбор
  только изменившихся). Для сотен заметок — миллисекунды; для десятков
  тысяч — нужен наблюдатель или инкрементальный обход.
- **Метка кода отрисовки — по исходникам ядра** (`crates/notes-core/build.rs`):
  в неё входит всё `src/`, кроме модулей из списка `AFTER_CACHE` (они
  работают после кэша). Правка любого другого файла ядра (даже
  комментария) — полный прогрев в отладочной сборке; забытый в списке
  модуль — тоже лишь лишний прогрев. Опасна обратная ошибка: код,
  влияющий на сырую отрисовку, вписать в `AFTER_CACHE` — кэш покажет
  старый HTML. Набор шрифтов в метке — семейства и число начертаний:
  заменённый файл системного шрифта с тем же набором не заметен.
- **Пределы кэша — константы**, не настройки: память — 64 МБ страниц
  (`page_cache::MEMORY_BUDGET`), диск — 512 МБ на все хранилища, чужие
  записи живут 14 дней (`cache::DISK_LIMIT`, `FOREIGN_TTL`). Чистка — при
  запуске прогрева (`notes serve`); `notes check` и `notes build` не
  чистят. Как закрыть, если понадобится: настройки в схеме.
- **Смена настроек рисунков читает сырую отрисовку с диска** (в памяти —
  только обработанная копия): у «Матана» — чтение ~3 МБ JSON и обработка,
  десятки миллисекунд на первый запрос после смены. Отладочная сборка и
  релиз, делящие `data/`, перезаписывают кэш друг друга (у них разная
  метка: библиотека каталогом и встроенная) — лишний прогрев.
- **Память процесса после прогрева — ~1,3 ГБ** (отладочная сборка,
  `tests/vault`): это кэши Typst (`comemo`), не страницы — страниц после
  прогрева в памяти 0 Б (было ~4,6 МБ). После перезапуска с готовым кэшем —
  ~70 МБ. Как закрыть: `comemo::evict(0)` после прогрева или прогрев в
  отдельном процессе; замерить скорость повторных сборок.
- **`Storage::list` обходит всё хранилище** (и не `.typ`: картинки, код)
  при каждом списке заметок, как раньше обход каталогов. Для базы данных
  (M5) — запрос; для папки на десятки тысяч файлов — наблюдатель или
  инкрементальный обход (см. «Индекс обходит хранилище»).
- **Метка `data-k-figs` — всё ещё `DefaultHasher`** (`figures.rs`): она в
  HTML страниц, замена хэша меняет снимки. Заменить на
  `version::StableHasher` вместе с ближайшим задуманным изменением
  отрисовки.

## Клиент

- **Раскрытые `<details>` («Ответы») при пересборке восстанавливаются по
  порядковому номеру** (`NoteView.svelte`): правка, добавившая блок
  выше, раскроет не тот. Как закрыть: ключ по якорю ближайшего раздела и
  тексту `summary`.
- **Значки — пакет `@lucide/svelte`** (ISC): в сборку идут только
  используемые, но `static.js` вырос 60 → 72 КБ (компонент значка тянет
  часть рантайма Svelte). На статическом сайте панель и оглавление — те же
  пути Lucide, но переписанные в CSS-маски (`baluk.css`): при обновлении
  значка — править в двух местах.

- **Граф: раскладка O(n²) на каждый фильтр** (`vault_graph.rs`: 400 шагов
  силовой модели + раздвигание) — теперь на сервере, в ответ на каждый
  переключатель страницы `/graph` и в каждой сборке заметки с
  `#vault-graph`. Сотня узлов — миллисекунды; тысячи — секунды. Как
  закрыть: решётка/квадродерево для отталкивания, кэш раскладки по фильтру.
- **Заметка с `#vault-graph` пересобирается при правке любой заметки**:
  её версия включает версию всего хранилища (все `.typ`), хотя граф
  зависит только от ссылок, тегов и состава заметок. С книгой и
  тяжёлыми рисунками рядом — лишние секунды. Как закрыть: версия — хэш
  самого ответа `/_vault/graph/…` (граф не изменился — заметка свежая).
- **Фильтр графа в пути файла** (`/_vault/graph/<JSON>.json`, `/` и `%`
  экранируются вручную в `graph.typ`): длинный фильтр — длинное имя; имя
  `_vault` в корне хранилища занято. Как закрыть: не нужно, пока фильтр
  маленький.
- **Подписи графа на картинке Typst мельчают у большого графа** (единица
  раскладки ужимается под `width`), живой граф в приложении — нет.
- **Переставленные руками узлы не запоминаются**: смена фильтра или
  перезагрузка — раскладка заново. Как закрыть: координаты в localStorage
  по id узла (как фильтры).
- **Физика графа — O(n²) на кадр** (`graph-physics.ts`: раздвигание всех
  пар), пока с графом что-то делают. Сотни узлов — доли миллисекунды;
  тысячи — рывки при перетаскивании. Как закрыть: решётка по размеру
  подписи (сравнивать только соседние клетки).
- **Физика графа — не силы ядра**: пружины к местам раскладки вместо
  отталкивания всех со всеми (иначе нетронутый граф поплыл бы — раскладка
  ядра не их точное равновесие). Протянутый узел не расталкивает дальние
  несвязанные узлы — только наехавшие. Как закрыть, если захочется
  «живее»: ядро отдаёт точное равновесие своих сил (без раздвигания), а
  подписи раздвигает клиент.
- **Подписи на экране крупнее раскладки ядра** (телефон, отдаление): узлы,
  чьи подписи наезжают уже в покое, раздвигаются по ужатым размерам —
  перетаскивание рядом может оставить их подписи наложенными, как и на
  картинке без движения.
- **После перетаскивания граф возвращается лишь на четверть** (так
  решили с пользователем: полный возврат пружинами «встряхивал» граф):
  соседи остаются почти там, куда их утянуло, и картинка расходится с PDF
  до перезагрузки или смены фильтра. Как закрыть, если понадобится: кнопка «вернуть раскладку»
  (плавный переезд к раскладке ядра).
- **Без движения (`prefers-reduced-motion`) соседи за узлом не тянутся** —
  двигается только сам узел; переходы и появление — мгновенные.
- **Ширина подписи узла — по числу знаков** (без замера шрифтом), поэтому
  раскладка одинакова везде; у очень широких или узких букв зазоры
  неточные. На телефоне граф вписывается мелко: подписи не мельче 8 px, при
  сильном отдалении видны только книги и найденное.
- **Касание узла на телефоне сразу открывает заметку**: наведения нет, и
  соседи узла подсвечиваются только на широком экране. Как закрыть: первое
  касание — подсветка, второе — переход.
- **Прерванная сборка продолжается на сервере**: ушли с книги, которая
  собирается, — сборка всё равно доработает (Typst не умеет отменять), и
  следующая заметка ждёт её. Плюс — возврат к книге потом мгновенный. Как
  закрыть: параллельные сборки разных заметок (свои `FileStore`) или отмена.
- **У статического сайта нет поиска, графа и страниц тегов**; оглавление —
  всегда два уровня (настроек у сайта нет). `static.js` — 87 КБ (рантайм
  Svelte, разборщик формул, значки, живой граф с физикой) даже у страниц
  без рисунков. Как закрыть:
  индекс поиска и граф JSON-файлами при сборке; скрипт рисунков —
  отдельным файлом, только где они есть.
- **Оглавление — плоский текст заголовков**: формулы в заголовках
  становятся текстом MathML (`ℝ𝑛` вместо $RR^n$). Как закрыть: отдавать из
  ядра HTML заголовка.
- **Проверка версии — опрос раз в N секунд** (по умолчанию 5, настройка). При
  многих вкладках/пользователях — лишние запросы; для M5 — SSE/WebSocket.

- **Разбор формул интерактивных рисунков написан дважды** — в Typst
  (`baluk/plots.typ`) и в TypeScript (`app/src/lib/plot/`). Расхождение
  ловит сверка на наборе формул (фикстура `Рисунки/Интерактив`, Vitest), но
  только для формул из набора. Как закрыть: считать в клиенте через
  Typst-в-WASM или отдавать сервером точки — дороже; пока — дописывать набор.
- **Подмножество формул узкое**: нет `if`, `calc.max/min`, пользовательских
  функций, параметрических кривых. Для рисунка целиком от параметра есть
  `frames` (кадры считает Typst); живой график с такими формулами — только
  расширением разборщика в обоих местах.
- **Кадры повторяют общее** (оси, рамку, неизменные части) в каждом SVG:
  ~4–8 КБ на кадр, отсюда предел 60 кадров. Как закрыть: в ядре выносить
  одинаковые пути кадров одного `k-frames` в общий `<defs>` (как глифы).
- **Размер кадров не выравнивается сам**: CeTZ подгоняет холст под
  нарисованное, и без невидимой рамки кадры разного размера смещаются.
  Как закрыть: в `frames` мерить кадры (`measure`) и дополнять до общего
  размера — но смещение начала координат так не исправить; пока — рамка
  руками (README).
- **В PDF — только кадр по умолчанию**: полосы из нескольких кадров
  (`pdf: "strip"`) нет. Как закрыть: опция `frames(…, pdf: (1, 4, 8))` —
  кадры в ряд через `in-row`.
- **Диапазон y/z по умолчанию — по кадру при значениях по умолчанию**: при
  другом значении параметра кривая уходит за поле. Лучше задавать `y:`/`z:`
  явно (README baluk).
- **3D — ортогональная проекция и алгоритм художника по центрам граней**:
  у сильно изогнутых поверхностей возможны огрехи перекрытия; нет осей с
  делениями у поверхности. Как закрыть: z-буфер в WebGL — если понадобится.
- **Вращение пальцем занимает жест на холсте** (`touch-action: none`):
  прокрутить страницу, начав с поверхности, нельзя. У 2D — `pan-y`,
  координаты касанием.
- **Демо интерактивных рисунков в `data/vault`** (раздел в «Возможности/
  Рисунки», два рисунка в «Интеграле Эйлера–Пуассона») — вне git: переданы
  вставками в описании PR.

## Хранилище

- **Хранилище-витрина живёт в `data/vault`, вне git** (как и положено данным
  пользователя). Потеря каталога — потеря витрины; тестовые фикстуры — в
  `tests/vault`. Как закрыть: синхронизация и история заметок (M5).

## Инструменты

- **Прогрев e2e — +20 с к прогону** (`e2e/global-setup.ts` собирает все
  19 заметок до сценариев): ради коротких ожиданий (10 с) и без ложных
  падений по тайм-ауту. Долгую первую сборку `01-switch` проверяет, дописав
  комментарий в файл заметки (кэш устаревает): проверяется повторная
  сборка, а не самая первая — для заглушки это одно и то же. Как закрыть,
  если прогон станет долгим: общий кэш на диске между прогонами (без
  `rm -rf tests/.data/e2e` — кэш годен, пока не менялся код отрисовки ядра).
- **`tools/check.sh` — последовательно и целиком** (~5 мин с e2e): шаги не
  параллелятся, `cargo test` и `clippy` собирают каждый своё. Шаг
  `api-types` сверяет типы с рабочим деревом git: выгруженные, но не
  закоммиченные типы — тоже «упал» (так задумано: коммитить вместе с Rust).
- **Подсказки клавиш прячутся по `(pointer: coarse)`**: на планшете с
  клавиатурой их тоже не будет (палитра, команды). Как закрыть — по
  отзывам: переключатель в настройках.
- **На телефоне вкладки только прокручиваются** — без свайпа между ними и
  без меню «все вкладки». Для Android (M4) — продумать заново.
- **`tools/shot.mjs` не эмулирует телефон** (`mobile: false`): с эмуляцией
  Chromium масштабирует окно и замеры врут. Узкую вёрстку проверяем шириной.
