# Технический долг

Что сознательно отложено или сделано упрощённо. Пополняется в конце каждой
итерации; закрытое — удалять (история — в git).

Формат: **что** — почему так — чем грозит — как закрыть.

## Отрисовка

- **Обработка рисунков — разбор текста SVG** (`figures.rs`), а не дерева:
  SVG существует только как вывод `typst-svg`. Опирается на его формат (тег
  за тегом, относительные команды пути `m l h v c q a Z`). Непонятное —
  оставляется как есть, но новая версия Typst может молча выключить
  сжатие. Как закрыть: тест на число слитых рисунков в `examples/vault`
  уже есть — следить при обновлении; в идеале — свой вывод кадров.
- **В кэше две копии страницы** (сырая и обработанная) — ради смены
  точности без перекомпиляции. «Матан» — ~5 МБ памяти. Для одного
  пользователя неважно; для сервера — хранить только сырую и обрабатывать
  при ответе (≈50 мс) или держать LRU.
- **Метка `data-k-figs` — хэш таблицы цветов**: две заметки на одной
  странице (вкладки M2) с одинаковой меткой не конфликтуют, с разными — тоже;
  но если тело вставлено без `<style>` из `styles`, рисунки станут без цвета.
  Клиенту — всегда вставлять `styles` вместе с `body`.
- **Каждая тема — полная компиляция.** Две темы = вдвое дольше, хотя текст
  одинаков, а различаются только рисунки. Как закрыть: компилировать текст
  один раз, а рисунки (`html.frame`) — по темам; нужна поддержка в Typst
  или своя раскладка кадров.
- **Книга — одна длинная страница.** «Матан» при первой сборке — ~14 с
  (отладочная сборка, 11 глав × 2 темы), страница — десятки тысяч пикселей.
  Как закрыть: страница на главу (`bundle`-экспорт Typst или своя разбивка по
  `k-h1`), релизная сборка.
- **`h`/`v` в HTML пропадают** (предупреждение «h was ignored»): горизонтальные
  и вертикальные отступы внутри текста теряются. Пока безобидно. Как закрыть:
  страховка `show h` → `span` с шириной, где величина абсолютная.
- **Скобки в формулах — эвристика.** `stretchy="false"` ставится, если между
  скобками нет дробей, корней, пределов, матриц (`render::TALL`). Высокие
  конструкции, не попавшие в список, получат нерастянутые скобки. Как
  закрыть: дополнять список по мере встречи; в идеале — исправление в Typst.
- **Изменение дерева typst-html после интроспекции** (typst#7951): ссылки
  внутри перенесённых вариантов рисунков разрешаются по базовому документу.
  Внутри рисунков ссылок пока нет.
- **Слаг якоря выбрасывает знаки:** «C++ и сборка» → `C-и-сборка`, два
  заголовка «C» и «C++» получат `C` и `C-2`. Как закрыть: транслитерация
  знаков (`+` → `plus`) или id по метке.

## Шрифты

- **Раздаются как есть (TTF/OTF), без woff2 и подмножеств**: статический сайт —
  ~9 МБ, из них шрифты ~6 МБ. Для localhost неважно; для VPS и Android — лишний
  трафик. Как закрыть: woff2 и подмножества по используемым глифам при сборке.
- **Список шрифтов для браузера зашит** в `notes-server` (`WEB_FONTS`), а не
  берётся из `theme.typ`. Новая тема со своим шрифтом потребует правки Rust.
- **Шрифты из коллекций (`.ttc`) не раздаются.** Сейчас такие не нужны.

## Ядро и сервер

- **Библиотека оформления берётся из репозитория** (путь по умолчанию —
  `CARGO_MANIFEST_DIR/../../konspekt`). Релизный бинарник вне репозитория её
  не найдёт без `--library`. Как закрыть: встроить `konspekt/` в бинарник
  (как `web/` через rust-embed) и отдавать из памяти.
- **Гонка версии:** версия считается по `stat` *после* компиляции. Если файл
  поменяли во время компиляции, клиент получит старый текст с новой версией и
  не перезапросит. Как закрыть: считать версию до компиляции и сравнивать.
- **Компиляции идут по одной** (общий `FileStore` под мьютексом). Для одного
  пользователя неважно; для сервера на много пользователей — узкое место.
- **Нет авторизации и HTTPS.** Сервер по умолчанию слушает только 127.0.0.1.
  До выкладки на VPS (M5) — обязательно.
- **Настройки одни на всё приложение** (`data/settings.json`), без пользователей.
- **`notes check` не проверяет ссылки заметки, которая не собралась.**
- **Версия — `DefaultHasher`**: не стабильна между версиями Rust; годится,
  пока версии живут в памяти процесса. Для синхронизации (M5) — свой хэш.

## Клиент

- **Временный клиент M1 — JS без сборки и типов.** Интерфейс M2 (TypeScript,
  фреймворк, Tauri) его заменит; переносить только логику обновления и настроек.
- **Нет оглавления, поиска, обратных ссылок, графа** — данные в API уже есть.
- **Проверка версии — опрос раз в N секунд** (по умолчанию 5, настройка). При
  многих вкладках/пользователях — лишние запросы; для M5 — SSE/WebSocket.

## Инструменты

- **`tools/shot.mjs` не эмулирует телефон** (`mobile: false`): с эмуляцией
  Chromium масштабирует окно и замеры врут. Узкую вёрстку проверяем шириной.
