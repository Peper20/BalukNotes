# Технический долг

Что сознательно отложено или сделано упрощённо. Пополняется в конце каждой
итерации; закрытое — удалять (история — в git).

Формат: **что** — почему так — чем грозит — как закрыть.

## Отрисовка

- **Обработка рисунков — разбор текста SVG** (`figures.rs`, `frames.rs`), а
  не дерева: SVG существует только как вывод `typst-svg`. Опирается на его
  формат (тег за тегом, относительные команды пути `m l h v c q a Z`).
  Непонятное оставляется как есть, но новая версия Typst может молча
  выключить сжатие. Как закрыть: следить за тестом числа слитых рисунков в
  `tests/vault` при обновлении; в идеале — свой вывод кадров.
- **Метка `data-k-figs` — хэш таблицы цветов**: тело заметки без `<style>`
  из `styles` останется без цветов рисунков. Клиенту — всегда вставлять
  `styles` вместе с `body`.
- **Каждая тема — полная компиляция** (параллельно): две темы — вдвое
  больше работы процессора. Исследование E1 (`docs/research/E1.md`): 95–99 %
  времени — рисунки, которые по темам собирать всё равно; «текст один раз»
  — не делаем. Компилирует устройство (ядро в приложении), и на телефоне
  параллельность не спасёт: там — ленивая вторая тема (roadmap, M6).
- **Первая сборка большой книги — секунды** («Матан» 7,4 с в релизе; почти
  всё — рисунки CeTZ). После перезапуска — кэш на диске; после правки главы
  неизменившиеся рисунки берёт memo Typst (0,05–0,17 с вместо 2,6–6,8 с,
  `docs/research/E2.md`). Медленно остаётся правка, пока сервер не работал,
  и после ≥ 10 сборок других заметок (`comemo::evict(10)` в `world.rs`). Как
  закрыть: вытеснять memo бережнее (по памяти, дольше хранить открытую
  заметку); сколько сборок помнить — настройка устройства (roadmap,
  «Настройки устройства»).
- **Главы книги режутся по тексту HTML** (`book.rs`), не по дереву: после
  обработки рисунков дерева уже нет. Опирается на то, что `typst-html`
  закрывает теги и экранирует `<`; непонятное — книга целиком.
- **Поиск браузера и печать видят одну главу книги**: в странице только
  показанная глава. Ctrl+F в книге по главам — поиск по всей книге
  (палитра), поиск браузера — повторное Ctrl+F; печать — через PDF (⎙).
- **HTML заголовка для оглавления вырезается из текста страницы**
  (`passes/heading_html.rs`): `typst-html` не умеет сериализовать отдельный
  элемент. Опирается на вид `<hN … id="…">`; ссылки в заголовке становятся
  текстом, заголовок с рисунком — текстом. При смене формата оглавление
  молча вернётся к тексту. Как закрыть: сериализация поддерева, если Typst
  её откроет.
- **Скобки в формулах — эвристика**: `stretchy="false"`, если между
  скобками нет дробей, корней, пределов, матриц (`passes/fences.rs`,
  `TALL`). Высокое, не попавшее в список, получит нерастянутые скобки. Как
  закрыть: дополнять список; в идеале — исправление в Typst.
- **Разделители якоря — список** (`render::SEPARATORS`: пробелы и обычная
  пунктуация); всё остальное остаётся в `id` — и редкая пунктуация (`¿`,
  `※`), и знаки формул в заголовке (`‖𝑥‖`). Как закрыть: дополнять список,
  если якоря станут неудобны.
- **Класс `k-h` — и у заголовков baluk, и у отступа `#h`** (`span.k-h`):
  правила отступа — только для `span.k-h`. Переименовать отступ — разом
  (библиотека, CSS, снимки).
- **`h`/`v` в HTML — только абсолютные** (страховка шаблона): `pt`, `em` и
  сумма — пустой `span.k-h`/`div.k-v`; `1fr` и проценты пропадают с
  предупреждением, `weak: true` не учитывается (добавить, когда встретится
  в заметках). Формулы страховка узнаёт по
  математическому шрифту темы: свой шрифт математики в заметке — и `quad`
  станет `span` внутри MathML.
- **Изменение дерева typst-html после интроспекции** (typst#7951): ссылки
  внутри перенесённых вариантов рисунков разрешаются по базовому документу.
  Внутри рисунков ссылок пока нет.
- **Проходы — три списка** (`passes::TREE`, `passes::TEXT`,
  `finish::FINISH`): зависимости между проходами не проверяются (сейчас их
  нет); каждый проход по дереву — отдельный обход (доли миллисекунды).
- **Общие части кадров — только целые поддеревья SVG** длиннее 96 байт,
  встреченные в группе дважды (`frames.rs`). По сети выигрыша почти нет
  (gzip и так сжимал повторы), выигрыш — в памяти и разборе браузером.

## Библиотека `baluk`

- **Словари оформления — только `ru` и `en`** (`i18n.typ`): другой язык —
  свои `words:` в заметке; недостающие слова — из английского словаря.
  `notes check` видит только буквальный `lang: "…"` в вызове `note`/`book`.
  Сообщения об ошибках библиотеки — всегда по-русски. Как закрыть: словари
  файлами хранилища (`/_words/de.typ`), если языков станет много.
- **Имена аргументов не входят в снимок API** (`baluk-api.txt` — только
  имена): Typst их не отдаёт, пришлось бы разбирать исходники.
- **Старые имена не поддерживаются**: заметки на прежнем русском API
  (`#рис`, `холст`, `#см`…) не собираются. Оригиналы конспектов вне проекта
  — на старом API; импорт оттуда — отдельный инструмент (решение
  пользователя).
- **Префикс `k-`** в классах, переменных и `data-k-*` — наследие прежнего
  имени. Пользователь решил оставить; переименовывать — разом (ядро, CSS,
  клиент, снимки).
- **Разбор формул интерактивных рисунков написан дважды** —
  `baluk/plots/formula.typ` и `app/src/lib/plot/formula.ts`. Расхождение
  ловит сверка на наборе формул (фикстура `Рисунки/Интерактив`, Vitest) —
  только для формул из набора. Как закрыть: Typst в WASM или точки с
  сервера — дороже; пока — дописывать набор.
- **Подмножество формул узкое**: нет `if`, `calc.max/min`, своих функций,
  параметрических кривых. Рисунок целиком от параметра — `frames`.
- **Диапазон y/z по умолчанию — по кадру при значениях по умолчанию**: при
  другом значении параметра кривая уходит за поле. Задавать `y:`/`z:` явно.
- **3D — ортогональная проекция и алгоритм художника по центрам граней**:
  у сильно изогнутых поверхностей возможны огрехи перекрытия, осей с
  делениями нет. Как закрыть: z-буфер в WebGL.
- **Размер кадров не выравнивается сам**: CeTZ подгоняет холст под
  нарисованное, без невидимой рамки кадры разного размера смещаются
  (README). Как закрыть: мерить кадры (`measure`) и дополнять — но сдвиг
  начала координат так не исправить.
- **Кадры в PDF — один ряд** (`pdf: (1, 4, 8)`, номера кадров): без
  переноса, широкие кадры вылезут за поле. Предел — 60 кадров на рисунок
  (не поднимать, пока заметке не понадобится — решение пользователя).
  Как закрыть: сетка с переносом (`columns:`).

## Шрифты

- **Математический шрифт не режется** (New Computer Modern Math, CFF с
  `MATH`): `fontcull` не умеет ни CFF, ни замыкание `MATH`. Отдаётся
  целиком — 669 КБ, самый тяжёлый файл страницы; подмножество с `MATH`
  дало бы 192 КБ (`docs/research/E3.md`). Как закрыть: подмножество в
  fontations/klippa, когда появится; или заранее нарезанные fontTools части
  в репозитории (проверить растягиваемые скобки в Chromium, WebKit, Gecko).
  Сейчас не делаем: оптимизация не задача (решение пользователя), ядро на
  устройстве отдаёт шрифт локально.
- **Части шрифта — по наборам знаков, а не по знакам страницы**: латиница
  грузится целиком (~40 КБ); кернинг между знаками разных частей теряется.
  Как закрыть: подмножество по знакам страницы.
- **Две копии brotli** (8 — `tower-http` и свой кодировщик CFF, 9 —
  `ttf2woff2`) и **вторая копия fontations** у `fontcull`: дольше сборка с
  нуля. Как закрыть: общая версия brotli; klippa напрямую.
- **Кэш частей шрифтов** (`<данные>/cache/fonts`, ~3,6 МБ) чистит сервер при
  запуске (`Fonts::prune_web`): части, которых нет в плане шрифтов тем,
  удаляются, если старше срока чужого кэша (другая сборка приложения делит
  каталог). Имя части — хэш шрифта, части и `webfonts::ENCODER`: версию
  кодировщика поднимать руками при правке `webfonts.rs` или обновлении
  `fontcull`.
  Первый запуск на новой машине — ~15 с процессора в фоне.
- **Шрифты из коллекций (`.ttc`) не раздаются.** Сейчас не нужны.
- **Шрифты оформления встроены целиком** (`fonts/`, 4,6 МБ) из пакетов
  Debian (`fonts-sil-gentiumplus` 6.200, `fonts-jetbrains-mono` 2.304 —
  возможны мелкие отличия от релиза JetBrains); встроенные семейства не
  подменить системными (только `--font-path`). Как закрыть: официальные
  релизы и новые снимки — с пользователем.

## Ядро и сервер

- **Метка кода отрисовки — по исходникам ядра** (`crates/notes-core/build.rs`):
  всё `src/`, кроме `AFTER_CACHE`. Правка любого другого файла (даже
  комментария) — полный прогрев. Опасна обратная ошибка: код, влияющий на
  сырую отрисовку, вписать в `AFTER_CACHE` — кэш покажет старый HTML. Набор
  шрифтов в метке — семейства и число начертаний, не содержимое файлов.
- **Встроенная библиотека не входит в версии заметок** (у файлов нет пути
  на диске): её хэш входит в метку кэша, новая библиотека — всё заново.
- **Кэш на диске чистит только `notes serve`** (при запуске прогрева); новые
  пределы из настроек — со следующей чистки.
- **Настройки устройства — в том же `settings.json`**: их отличает признак
  `device` в схеме; синхронизация (M4) обязана его учитывать. Значения
  по умолчанию для телефона — на глаз (roadmap).
- **Смена настроек рисунков читает сырую отрисовку с диска** («Матан» —
  ~3 МБ JSON, десятки мс). Отладочная и релизная сборки, делящие каталог данных,
  перезаписывают кэш друг друга (разная метка) — лишний прогрев.
- **Память процесса после прогрева — ~1,35 ГБ** (отладочная сборка,
  `tests/vault`, замер 2026-09-29, dhat): ~0,85 ГБ — ёмкость структур
  `comemo` (slab и хэш-таблицы деревьев вызовов), которую `evict` не
  сжимает даже при пустом кэше; `evict(0)` освобождает лишь ~15 МБ, смена
  аллокатора не помогает (mimalloc — 1,25 ГБ). С правкой `comemo` (копия в
  `vendor/`: пустое дерево пересоздаётся) — 0,69 ГБ; остальное — живые
  данные и фрагментация (mimalloc поверх — ещё −0,13 ГБ, не подключён).
  С готовым кэшем после перезапуска — ~70 МБ.
  Освобождение — только после большого прохода прогрева и не чаще раза в
  10 минут (`warm::should_release`): обычная правка memo не теряет.
- **Параллельные сборки — пул кэшей файлов** (`world::Stores`): число —
  настройка устройства (по умолчанию 2), память — до «число сборок» раз
  больше. `comemo::evict(N)` после сборки чистит и чужой memo; большой
  проход прогрева забывает всё (`evict(0)`) — и memo открытой заметки.
- **Прогрев и пользователь делят процессор**: запрос не ждёт сборку
  прогрева, но идёт рядом. Поток сборки прогрева — с `nice` 10 (Linux,
  Android; `rustix`), но пул вёрстки самого Typst — общий, без понижения.
  На других ОС приоритет не меняется. Порядок новых заметок — по размеру
  исходников (приближение).
- **Прерванная сборка продолжается** (Typst не умеет отменять): ушли с
  собирающейся книги — она доработает. Как закрыть: отмена сборки.
- **Наблюдатель файлов — только у сервера и только каталога**
  (`notes-core::watch`): CLI обходит хранилище. События ОС теряются
  (переполнение inotify, сетевые диски, файл в только что созданной
  папке), поэтому индекс и прогрев всё равно обходят хранилище не реже раза
  в 10 минут (`graph::MAX_AGE`, `warm::RESCAN`); сломанный наблюдатель
  (и переполненная очередь — `Rescan`) выключается, поток `/api/events`
  закрывается, и клиент переходит на опрос. Каталог библиотеки на диске
  (`/_baluk/` отладочной сборки) наблюдается вторым источником
  (`Changes::also`); его сбой — только предупреждение. Правка библиотеки
  устаревает все заметки — прогрев собирает хранилище заново. С наблюдателем индекс после изменения
  обходится целиком, не по путям из события; `Storage::list` без него — обход всего хранилища.
  Для десятков тысяч заметок и базы данных — обновлять по путям.
- **Вычисляемые ссылки — из последней удачной сборки** (`Record.links`):
  до пересборки в обратных ссылках и графе видны и удалённые из исходника
  ссылки; несобранная заметка даёт только буквальные `#see("путь")`.
- **Версия заметки с `#vault-graph` — ответ графа**: проверка версии строит
  индекс и берёт раскладку (из кэша); правка ссылок в большом хранилище —
  новая раскладка уже при проверке версии.
- **Данные хранилища для заметок — один поставщик** (граф,
  `vault_data.rs`); отпечаток по умолчанию — хэш ответа, дешёвый признак
  свежести поставщик может задать сам (`DataProvider::token`). Фильтр
  графа — в имени файла (`/_vault/graph/<JSON>.json`), имя `_vault` в
  корне хранилища занято.
- **Хранилище не собирается обычным `typst compile`** (`/_baluk/` есть
  только в приложении); PDF — через приложение, на каждый запрос без кэша
  («Матан» ~2 с).
- **HTML заметки не очищается**: Typst выдаёт любые элементы и атрибуты
  (`html.elem`), клиент вставляет их `innerHTML` — обработчик вроде
  `onerror` в заметке исполнится. Пока заметки пишет сам пользователь —
  терпимо; до синхронизации с сервером — список разрешённых тегов и
  атрибутов в ядре и CSP (roadmap M4).
- **Вместо входа — общий токен без срока** (`auth.rs`): `?token=` остаётся
  в адресной строке, истории и журнале, cookie без срока и без `Secure`,
  404 отвечает и без токена; HTTPS нет. Для `notes serve` на своём
  компьютере (127.0.0.1) терпимо; до выкладки сервера в сеть — вход с
  сессией по roadmap M4 (решено пользователем), токен и `?token=` убрать.
- **Нет CORS**: `base` в `app/src/lib/api/config.ts` есть, но сервер не
  пускает чужой `Origin`. Интерфейс ходит к ядру на своём устройстве (тот
  же адрес или схема Tauri); к серверу-хранилищу ходит ядро, а не
  страница, — CORS понадобится, только если страница из другого источника
  обратится к серверу сама.
- **События клиенту — «что-то изменилось»** (`GET …/events`): каждая
  вкладка на любую правку сверяет версию заметки и список (два дешёвых
  запроса); одна вкладка — одно соединение (у HTTP/1.1 предел ~6 на
  сервер). Для многих пользователей — события по заметкам.
- **Настройки одни на всё приложение** (`settings.json` каталога данных),
  у хранилищ своих нет: решено хранить их в самом хранилище
  (`<хранилище>/.baluk/`), но какие настройки — хранилища, а какие —
  общие, не решено (`docs/questions.md`).
- **Открытое хранилище не закрывается**: у каждого — своё ядро (шрифты,
  темы, страницы в памяти до 64 МБ, наблюдатель файлов, поток прогрева) до
  остановки сервера; перебрали десяток хранилищ — память растёт. Шрифты и
  темы загружаются заново на каждое (~0,5 с открытия) и ещё раз — у ядра
  без хранилища (темы и шрифты для браузера), хотя библиотека одна. Как закрыть: закрывать неактивные хранилища по времени; общие
  `Fonts` и `ThemeSet` на все ядра.
- **Активное хранилище (его прогревают) — открытое или подсказавшее
  прогрев последним**: две вкладки браузера с разными хранилищами
  перетягивают прогрев при каждом запуске клиента. Пропущенное собирается
  по запросу — медленнее, но верно.
- **Удаление — только в корзину системы** (`Storage::trash`): на Android и
  в WASM её нет — удалить нельзя (ошибка); вернуть заметку из приложения
  нельзя (только из корзины Dolphin); пустые папки после удаления
  остаются на диске. При синхронизации (M4) удаление должно стать
  изменением с версией (иначе заметка вернётся с сервера) — продумать там
  же. Как закрыть: корзина хранилища `.trash/` там, где нет системной.


## Граф

- **Раскладка ядра — ~0,5 с на 1000 узлов** (релиз, первый раз): решётка
  отсекает только дальние пары, радиус отталкивания — четыре ребра.
  Повторно — кэш `Layouts`. Как ускорить: другая модель (Барнс — Хат);
  картинки графов изменятся — пользователь разрешил (roadmap M3).
- **Физика клиента — пружины к раскладке ядра, а не силы ядра**: иначе
  нетронутый граф поплыл бы. Протянутый узел расталкивает только наехавших.
  Решётка (с 200 узлов) — клетка по самому большому узлу: одна длинная
  подпись возвращает почти полный перебор.
- **Переставленные узлы не запоминаются**: смена фильтра или перезагрузка —
  раскладка заново. Вернуть раскладку — кнопка ↶ только на `/graph`.
  Запоминать ли — вопрос вкуса пользователя.
- **Ширина подписи — по числу знаков** (без замера шрифтом): раскладка
  одинакова везде, зазоры у широких букв неточные. Подписи на экране
  крупнее раскладки (телефон) могут наезжать; картинка Typst большого
  графа мельчит подписи.
- **Касание узла на телефоне сразу открывает заметку**, соседи
  подсвечиваются только наведением. Решает пользователь (M6, Android).
- **Без движения (`prefers-reduced-motion`)** соседи за узлом не тянутся,
  переходы мгновенные.

## Клиент

- **Раскрытые «Ответы» — по якорю раздела и тексту `summary`**
  (`lib/details.ts`), среди одинаковых — по номеру: новый блок выше
  раскрытого с тем же текстом раскроется вместо него.
- **Опрос версии — запасной путь**: без событий — раз в 5 с
  (`changes::POLL_SECONDS`, константа).
- **Подсказки клавиш прячутся по `(pointer: coarse)`**: на планшете с
  клавиатурой их тоже нет.
- **На телефоне вкладки только прокручиваются** — без свайпа и списка
  вкладок. Для Android (M6) — продумать заново.
- **Вращение 3D пальцем занимает жест** (`touch-action: none`): прокрутить
  страницу, начав с поверхности, нельзя.

## Хранилище и инструменты

- **Название — текстом из исходника** (`outline.rs`): формулы и
  вычисляемое (`#let`) в `title: […]` пропускаются — `[Ряд $sum 1/n^2$]` в
  дереве, вкладках и в `#see` без подписи станет «Ряд». Как закрыть:
  брать название собранной страницы (оно есть в `Rendered.title`, но только
  после сборки) или отдавать клиенту HTML названия.
- **Название папки — только `_folder.toml`**: ни интерфейса, ни команды
  (`notes` его не создаёт, пишут руками или агент по навыку); `_folder.toml`
  в папке книги не читается. Папка без заметок (только `_folder.toml`) в
  дереве не видна.
- **Индекс ссылок подписывает `#see` без подписи именем файла**
  (`outline.rs`: текст ссылки для поиска), а страница — названием цели:
  поиск по тексту ссылки находит имя файла. Как закрыть: подставлять
  названия при сборке индекса (нужны названия всех заметок — второй проход).
- **Имя файла из названия — без нормализации Юникода** (`new_note::file_name`):
  «й» из двух кодовых точек (macOS) и из одной — разные имена, проверка
  занятости их не сравнит. Как закрыть: NFC при создании и сравнении.
- **`/_vault/title/…` без наблюдателя обходит хранилище** на каждое
  название (CLI `notes check`: заметка с 10 ссылками — 10 обходов `stat`).
  Сейчас десятки мс; растёт с хранилищем. Как закрыть: кэш обхода на время
  одной команды.

- **Хранилища пользователя — вне git и без копий**
  (`~/.local/share/baluk-notes/vaults/`): потеря каталога — потеря заметок
  (витрина, копии конспектов, свои заметки). Тестовые фикстуры —
  `tests/vault`. Как закрыть: отдельный git-репозиторий хранилища или
  синхронизация с сервером (M4).
- **e2e «вернуть раскладку» нестабилен** (`graph.spec.ts`, 2026-09-29: на
  `main` 7 падений из 20, на ветке 5 из 20): проверка «расстояние до дома
  только убывает» зависит от кадров браузера. Как закрыть: допуск по времени или проверка по
  раскладке, а не по кадрам.
- **Прогрев e2e — +20 с к прогону** (`e2e/global-setup.ts`): ради коротких
  ожиданий (10 с). `01-switch` проверяет повторную долгую сборку (дописывает
  комментарий в заметку), а не самую первую.
- **`tools/check.sh` — последовательно** (~4 мин с e2e); шаг `api-types`
  сверяет типы с рабочим деревом: выгруженные, но не закоммиченные — тоже
  «упал».
- **Установленные `notes` и навык `/baluk-note` — снимок на момент
  `tools/install.sh`** (друг с другом согласованы): без переустановки после
  изменений проекта они отстают от репозитория, а `notes serve` старой
  версии работает до перезапуска. Отладочная сборка из репозитория и
  установленная делят каталог данных — кэш перезаписывается (разная
  метка). Как закрыть: приложение с обновлением (M5).
- **Копия `comemo` с правкой** (`vendor/comemo`, `[patch.crates-io]`):
  при обновлении Typst — перенести правку в версию, которую он тянет, или
  убрать копию, если правка вышла. Предложить её в `typst/comemo` —
  решение пользователя.
- **Файл настроек `notes` — один ключ** (`data` в
  `~/.config/baluk-notes/config.toml`, неизвестный ключ — ошибка).
  Хранилища по умолчанию нет — `--vault` в каждой команде заметок
  (длиннее, зато без ошибки «не то хранилище»). Адрес
  сервера в `notes new` и навыке — по умолчанию (`127.0.0.1:8421`), свой
  `--addr` они не знают.
- **Навык смотрит страницу в приложении через Claude in Chrome**: без него
  (или без запущенного `notes serve`) — только PDF.
- **`docs/writing.md` и `SKILL.md` сверяются с библиотекой частично**: тест
  (`--test library`) проверяет только вызовы `#имя`; имена без `#`
  (`side-by-side`, `pdf:`, аргументы) и смысл правил устареют незаметно —
  правило в `CLAUDE.md`: править вместе с библиотекой. Из сниппетов
  `SKILL.md` собирается только блок «Common calls»; шапка в разделе «The
  file» переписана с `notes-core::new_note` руками.
- **Справочник навыка (`skills/baluk-note/reference.md`) сверяется только
  по именованным параметрам**: тест находит `#let имя(…)` в исходниках
  `baluk/` текстом (не через Typst) и сравнивает имена и значения по
  умолчанию. Позиционные аргументы, описания и допустимые строки
  (`"shaded"`, ключи словарей) не проверяются — их ловит только сборка
  примеров. Сигнатуры описаны дважды: `baluk/README.md` (для людей и
  `notes docs library`) и `reference.md` (для навыка). Как закрыть:
  собирать `reference.md` из комментариев `///` у функций при установке.
- **Правила содержания — в двух местах**: `docs/writing.md` (по-русски,
  `notes docs writing`) и `SKILL.md` (по-английски, раздел «Writing a
  good note»), навык самодостаточен. Правишь правило — правь оба. Как закрыть:
  один источник — английский текст правил, `writing.md` — ссылка на него
  (или перевод при установке), если расхождения начнут случаться.
- **Навык рассчитан на Claude Code**: `allowed-tools`,
  `disable-model-invocation`, «Base directory» — его понятия; другие
  оболочки (opencode) читают `SKILL.md` как текст, путь к `examples/`
  модель берёт из строки «Base directory», если оболочка её пишет.
- **Подсказка «путь начинается с имени каталога хранилища»** в `notes new`
  — эвристика по первому сегменту (`Заметки/Тема`, если папки `Заметки` в
  хранилище нет); другие ошибки пути от каталога данных она не ловит.
- **Вкладки и места чтения прежней версии клиента** (`k-tabs` и др. без
  хранилища в ключе) не переносятся: после обновления — один раз с чистого
  листа.
- **Другое хранилище — перезагрузка страницы** (состояние клиента — на
  одно хранилище): для десктопа (M5) — одно окно на хранилище, как в
  Obsidian, или пересоздание состояния без перезагрузки.
- **`tools/shot.mjs` не эмулирует телефон** (`mobile: false`): с эмуляцией
  замеры врут; узкую вёрстку проверяем шириной.
- **Полная отладочная информация Rust — десятки ГБ в `target/`**: в облаке
  переполняет диск. Там собирать с `CARGO_PROFILE_DEV_DEBUG=line-tables-only`.
