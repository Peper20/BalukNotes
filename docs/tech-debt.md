итерации; закрытое — удалять (история — в git).

## Отрисовка

- **Обработка рисунков — разбор текста SVG** (`figures.rs`), а не дерева:
  SVG существует только как вывод `typst-svg`. Опирается на его формат (тег
  за тегом, относительные команды пути `m l h v c q a Z`). Непонятное —
  оставляется как есть, но новая версия Typst может молча выключить
  сжатие. Как закрыть: тест на число слитых рисунков в `tests/vault`
  уже есть — следить при обновлении; в идеале — свой вывод кадров.
- **Метка `data-k-figs` — хэш таблицы цветов**: две заметки на одной
  странице (вкладки M2) с одинаковой меткой не конфликтуют, с разными — тоже;
  но если тело вставлено без `<style>` из `styles`, рисунки станут без цвета.
  Клиенту — всегда вставлять `styles` вместе с `body`.
- **Каждая тема — полная компиляция** (параллельно, в своём потоке): две
  темы — больше вдвое работы процессора. Исследование E1
  (`docs/research/E1.md`): 95–99 % времени — рисунки, которые по темам
  собирать всё равно; «текст один раз» дал бы ≤ 4 % процессора у заметок с
  рисунками и ~0 по времени ожидания — не делаем. На телефоне (M4, мало
  ядер) выгоднее ленивая вторая тема: собрать тему, которую читают,
  показать, вторую — потом (клиенту — склейка по приходу).
- **Первая сборка большой книги — секунды** («Матан» 7,4 с в релизе; почти
  всё время — рисунки CeTZ). Кэш на диске убирает её после перезапуска;
  после правки главы неизменившиеся рисунки берёт memo Typst — пересборка
  0,05–0,17 с вместо 2,6–6,8 с (исследование E2, `docs/research/E2.md`).
  Медленно остаётся: правка, пока сервер не работал, и после ≥ 10 сборок
  других заметок (`comemo::evict(10)` в `world.rs` вытесняет memo). Как
  закрыть: вытеснять memo бережнее (дольше хранить записи последней
  собранной пользователем заметки, `evict` по памяти) — вместе с пределами
  памяти сервера; своя вёрстка рисунков с кэшем на диске — дорого.
- **Ctrl+F и печать видят одну главу книги**: в странице только показанная
  глава (её отдаёт сервер). Поиск по книге — команда палитры «Поиск в этой
  книге» (все главы, по порядку текста), печать — через PDF (⎙). Сам Ctrl+F
  браузера по-прежнему ищет в одной главе; перехватывать его — вопрос к
  пользователю (`docs/questions.md`).
- **Главы режутся по тексту HTML** (`notes-core::book`), не по дереву
  typst-html: после обработки рисунков дерева уже нет. Опирается на то, что
  `typst-html` закрывает теги и экранирует `<`; непонятное — книга
  показывается целиком. Соседние главы клиент грузит заранее
  (`app/src/lib/chapters.ts`, через 300 мс после показа): переход на
  соседнюю — без сервера, на дальнюю (оглавление) — запрос.
- **`h`/`v` в HTML — только абсолютные** (`template.typ`, страховка
  `_web-template`): `pt`, `em` и их сумма становятся пустым `span.k-h` /
  `div.k-v`; доли (`1fr`) и проценты по-прежнему пропадают с предупреждением
  («h was ignored»), `weak: true` не учитывается (пустой элемент в начале
  строки — всё равно отступ). Формулы страховка узнаёт по шрифту
  (`text.font` — математический шрифт темы): свой шрифт математики в
  заметке — и `quad` станет `span` внутри MathML. Как закрыть: признак
  «внутри формулы» от Typst, когда появится.
- **Скобки в формулах — эвристика.** `stretchy="false"` ставится, если между
  скобками нет дробей, корней, пределов, матриц (`render::TALL`). Высокие
  конструкции, не попавшие в список, получат нерастянутые скобки. Как
  закрыть: дополнять список по мере встречи; в идеале — исправление в Typst.
- **Изменение дерева typst-html после интроспекции** (typst#7951): ссылки
  внутри перенесённых вариантов рисунков разрешаются по базовому документу.
  Внутри рисунков ссылок пока нет.
- **Словами в якоре — только `+ # % & @`** (`render::SIGN_WORDS`:
  `C++` → `C-plus-plus`): остальные знаки (`=`, `*`, `<`, `→`…) — по-прежнему
  разделители, и «a=b» и «a b» получат один слаг (второй — `-2` по порядку).
  Слова английские и в русском тексте. Смена слагов меняет адреса разделов:
  старые закладки на `#C-и-сборка` ведут в начало заметки. Как закрыть:
  дописывать знаки в таблицу по мере встречи (и обновлять снимки).

- **Проходы — три списка, а не один** (`passes::TREE`, `passes::TEXT`,
  `finish::FINISH`): проход по дереву не может идти после сериализации, а
  проходы после кэша зависят от настроек. Порядок внутри списка — явный,
  но зависимости между проходами не проверяются (сейчас их нет). Каждый
  проход по дереву — отдельный обход (5 обходов вместо одного, доли
  миллисекунды).
- **Общие части кадров — только целые поддеревья SVG** (`frames.rs`), и
  только если встречаются в группе дважды и длиннее 96 байт; разбор — по
  тексту, как в `figures`. Путь, меняющийся от кадра к кадру хоть на
  точку, выносится целиком каждый раз. По сети выигрыша почти нет (gzip и
  так сжимал повторы: 8,4 → 8,5 КБ у «Кадров»), выигрыш — в памяти и
  разборе браузером (95 → 65 КБ). Предел 60 кадров (`baluk/frames.typ`)
  можно поднимать — это задача библиотеки.

## Библиотека `baluk`

- **Словари оформления — только `ru` и `en`** (`i18n.typ`): другой язык —
  свои `words: (…)` в каждой заметке (или словарь в библиотеке); чего нет в
  `words:`, берётся из русского словаря. `notes check` предупреждает о
  `lang:` без словаря и без `words:` — только буквальный `lang: "…"` в
  вызове `note`/`book` (`notes-core::lint`), не вычисленный. Сообщения об
  ошибках библиотеки — всегда по-русски. Как закрыть: словари как файлы
  хранилища (`/_words/de.typ`), если языков станет много.
- **Старые имена не поддерживаются**: заметки на прежнем русском API
  (`#рис`, `холст`, `#см`…) не собираются, слоя совместимости нет. Копии в
  `data/vault` и фикстуры переведены; оригиналы конспектов вне проекта — на
  старом API, и новый импорт оттуда требует перевода. Решено (2026-09-26):
  переводчик старого API не храним — импорт заменит новый инструмент на
  основе BalukNotes.
- **Префикс `k-` в классах, CSS-переменных и `data-k-*`**, `K_THEMES` в
  статическом сайте — наследие прежнего имени библиотеки. Вреда нет, но имя
  не говорит о проекте. Пользователь (2026-09-26): оставить. Если понадобится —
  переименовать разом (ядро, CSS, клиент, снимки).

## Шрифты

- **Математический шрифт не режется** (New Computer Modern Math, CFF с
  таблицей `MATH`): `fontcull` не умеет ни CFF, ни замыкание `MATH`, а без
  него пропали бы растягиваемые скобки. Отдаётся целиком в WOFF2 — 669 КБ,
  самый тяжёлый файл страницы. Исследование E3 (`docs/research/E3.md`):
  подмножество с `MATH` (fontTools) «латиница, греческий, операторы,
  стрелки, курсив» — 192 КБ. Как закрыть: подмножество с `MATH` в
  fontations/klippa, когда появится; или заранее нарезанные fontTools части
  в репозитории (пересобирать при замене шрифта или Typst; проверить
  растягиваемые скобки в Chromium, WebKit, Gecko).
- **Части шрифта — по наборам знаков, а не по знакам страницы**: латиница
  грузится целиком (~40 КБ), даже если на странице три латинские буквы.
  Кернинг между знаками из разных частей теряется (кавычки «» из латиницы
  рядом с кириллицей). Как закрыть: подмножество по знакам сайта при
  `notes build` — ценой пересжатия при каждой сборке.
- **Две копии brotli** (8 — у `tower-http` и своего кодировщика WOFF2 для
  CFF, 9 — у `ttf2woff2`, WOFF2 с преобразованием `glyf`): дольше сборка с
  нуля. Как закрыть: перейти на brotli 9 вместе с
  `tower-http` или свой кодировщик CFF — через `ttf2woff2`, когда он научится CFF.
- **Кэш частей шрифтов не чистится** (`data/cache/fonts`, ~3,6 МБ): после
  замены шрифта или кодировщика старые части остаются (имя — хэш шрифта,
  части и версии кодировщика `webfonts::ENCODER`, поэтому не мешают). Первый
  запуск на новой машине — по-прежнему ~15 с процессора в фоне. Версию
  кодировщика нужно поднимать руками при правке `webfonts.rs` или
  обновлении `fontcull`. Как закрыть: чистка по времени доступа, как у
  страниц.
- **`fontcull` тянет свою копию fontations** (`fontcull-read-fonts`,
  `-skrifa`, `-klippa`): вторая копия рядом с той, что у Typst, — дольше
  сборка с нуля. Как закрыть: klippa из fontations напрямую, когда её
  опубликуют.
- **Шрифты из коллекций (`.ttc`) не раздаются.** Сейчас такие не нужны.
- **Шрифты оформления встроены в бинарник целиком** (`fonts/`, 4,6 МБ: Gentium
  Plus и JetBrains Mono, по 4 начертания) — ради одинаковой отрисовки везде.
  Файлы взяты из пакетов Debian (`fonts-sil-gentiumplus` 6.200 — сборка SIL;
  `fonts-jetbrains-mono` 2.304 — Debian собирает из исходников, возможны
  мелкие отличия от релиза JetBrains). Чем грозит: +4,6 МБ к бинарнику;
  встроенные семейства нельзя подменить системными (только `--font-path`).
  Как закрыть: при желании — заменить файлы официальными релизами (SIL,
  GitHub JetBrains) и обновить снимки.

## Ядро и сервер

- **Прогрев и пользователь делят процессор**: сборки разных заметок идут
  параллельно, поэтому запрос открытой заметки не ждёт сборку прогрева, но
  идёт рядом с ней (прогрев не начинает новую, пока кто-то ждёт). Порядок
  ещё не собиравшихся заметок — по размеру исходников (приближение: время
  решают рисунки CeTZ); собиравшихся — по времени прошлой сборки из кэша.
  Как закрыть, если понадобится: пониженный приоритет потоков прогрева.
- **Наблюдатель файлов — только у сервера и только каталога**
  (`notes-core::watch`, `DirStorage::watch` через `notify`): CLI (`check`,
  `build`) обходит хранилище, как раньше. События ОС теряются (переполнение
  очереди inotify, сетевые и смонтированные диски, файл в только что
  созданной папке — одно событие папки): поэтому индекс всё равно
  обходится не реже раза в 10 минут (`graph::MAX_AGE`), прогрев — тоже
  (`warm::RESCAN`), а сломавшийся наблюдатель выключается (дальше — обход).
  Версия заметки — по-прежнему `stat` её файлов на каждый запрос версии.
  Лимит inotify (`max_user_watches`) на огромном хранилище может кончиться —
  в журнале будет предупреждение, работа — обходом.
- **Встроенная библиотека не входит в версии заметок**: у её файлов нет
  пути на диске. Вместо этого её хэш входит в метку кэша на диске
  (`LibrarySource::fingerprint`, считается при запуске): новая библиотека —
  всё собирается заново. В отладочной сборке по умолчанию берётся каталог
  `baluk/`, и правки видны. `--library` в релизе — тоже каталог.
- **Хранилище не собирается обычным `typst compile`**: `/_baluk/` есть
  только в приложении. PDF — через приложение (`notes pdf`, кнопка ⎙). Как
  закрыть, если понадобится: команда выгрузки библиотеки в хранилище.
- **PDF собирается на каждый запрос** (без кэша): «Матан» — ~2 с. Для
  одного пользователя приемлемо.
- **Параллельные сборки — пул кэшей файлов** (`world::Stores`): у каждой
  одновременной сборки свой `FileStore` (исходники и файлы разбираются в
  каждом заново, память — до «число сборок» раз больше), одновременно — до
  половины ядер, но не меньше двух (`max_parallel`, константа). Кэш
  `comemo` — общий, `comemo::evict(10)` после каждой сборки чистит и
  чужой (результат верен, лишь дольше). Для сервера на много пользователей
  предел стоит сделать настройкой.
- **Нет авторизации и HTTPS.** Сервер по умолчанию слушает только 127.0.0.1.
  Есть только общий токен (`serve --token`, для Tauri): один на всех, без
  пользователей и срока. До выкладки на VPS (M5) — обязательно.
- **Токен — упрощённо** (`notes-server/src/auth.rs`): cookie без `Secure`
  (localhost по HTTP), токен из `?token=` остаётся в адресной строке и
  истории до перехода; неизвестные пути (404) отвечают и без токена.
  Клиент шлёт токен сам, если он задан (`app/src/lib/api/config.ts`:
  заголовок у запросов, `?token=` у PDF, событий и стилей — в адресе,
  значит и в журнале сервера). Для Tauri достаточно; для сети — HTTPS и
  настоящая авторизация (M5).
- **Сервер на другом адресе, чем клиент, — без CORS**: `base` в
  `api/config.ts` уже есть, но сервер не отвечает заголовками CORS и не
  пускает чужой `Origin`. Сейчас клиент всегда отдаёт тот же сервер
  (Tauri тоже открывает `http://127.0.0.1:<порт>/`). Как закрыть, если
  клиент понадобится отдельно (Tauri со своими файлами, VPS с CDN): слой
  CORS в `notes-server` с белым списком.
- **События клиенту — «что-то изменилось», без адресата** (`GET
  /api/events`): каждая вкладка на любую правку сверяет версию показанной
  заметки и список заметок (два дешёвых запроса). Пути изменившихся файлов
  в событии есть, но клиент их не разбирает (какие файлы у заметки, знает
  сервер). При многих пользователях (M5) — события по заметкам.
- **Настройки одни на всё приложение** (`data/settings.json`), без пользователей.
- **Вычисляемые ссылки — из последней удачной сборки** (`Record.links`,
  `SourceIndex::set_built`): ещё не собранная заметка даёт в обратные ссылки
  и граф только буквальные `#see("путь")`, а после правки, до пересборки
  (прогрев — до минуты), — ещё и прежние ссылки, даже удалённые из
  исходника. `notes check` у несобравшейся заметки проверяет ссылки из
  индекса (буквальные и прежней сборки), у собравшейся — из страницы.
- **Без наблюдателя индекс обходит хранилище при каждом запросе** (`stat`
  всех файлов, разбор только изменившихся): так у CLI и при сломанном
  наблюдателе. С наблюдателем — обход только после изменения, но целиком
  (не только изменившиеся файлы). Для десятков тысяч заметок — обновлять
  индекс по путям из события.
- **Метка кода отрисовки — по исходникам ядра** (`crates/notes-core/build.rs`):
  в неё входит всё `src/`, кроме модулей из списка `AFTER_CACHE` (они
  работают после кэша). Правка любого другого файла ядра (даже
  комментария) — полный прогрев в отладочной сборке; забытый в списке
  модуль — тоже лишь лишний прогрев. Опасна обратная ошибка: код,
  влияющий на сырую отрисовку, вписать в `AFTER_CACHE` — кэш покажет
  старый HTML. Набор шрифтов в метке — семейства и число начертаний:
  заменённый файл системного шрифта с тем же набором не заметен.
- **Пределы кэша — константы**, не настройки: память — 64 МБ страниц
  (`page_cache::MEMORY_BUDGET`), диск — 512 МБ на все хранилища, чужие
  записи живут 14 дней (`cache::DISK_LIMIT`, `FOREIGN_TTL`). Чистка — при
  запуске прогрева (`notes serve`); `notes check` и `notes build` не
  чистят. Как закрыть, если понадобится: настройки в схеме.
- **Смена настроек рисунков читает сырую отрисовку с диска** (в памяти —
  только обработанная копия): у «Матана» — чтение ~3 МБ JSON и обработка,
  десятки миллисекунд на первый запрос после смены. Отладочная сборка и
  релиз, делящие `data/`, перезаписывают кэш друг друга (у них разная
  метка: библиотека каталогом и встроенная) — лишний прогрев.
- **Память процесса после прогрева — ~1,3 ГБ** (отладочная сборка,
  `tests/vault`): это кэши Typst (`comemo`), не страницы — страниц после
  прогрева в памяти 0 Б (было ~4,6 МБ). После перезапуска с готовым кэшем —
  ~70 МБ. Как закрыть: `comemo::evict(0)` после прогрева или прогрев в
  отдельном процессе; замерить скорость повторных сборок.
- **`Storage::list` обходит всё хранилище** (и не `.typ`: картинки, код),
  если наблюдатель не работает; с ним `DirStorage` помнит список до первого
  события создания, удаления или переименования. Для базы данных (M5) —
  запрос.

## Клиент

- **Раскрытые `<details>` («Ответы») — по якорю раздела и тексту
  `summary`** (`lib/details.ts`), а среди одинаковых в разделе — по номеру:
  второй блок «Ответы» в том же разделе, добавленный выше раскрытого,
  раскроется вместо него. Переименование раздела сворачивает его блоки.
- **Значки — два пакета Lucide** (ISC): приложение — `@lucide/svelte`
  (в сборку идут только используемые; компонент значка тянет часть
  рантайма Svelte), сайт — CSS-маски, которые сборка `baluk.css` делает из
  `@lucide/icons` (`lucide("имя", толщина)`). Версии пакетов держатся
  равными руками: разойдутся — значок на сайте и в приложении может чуть
  отличаться. Как закрыть: шаг `tools/check.sh`, сверяющий версии, или
  брать данные значков для сайта из `@lucide/svelte`, если он их откроет.

- **Раскладка графа — всё ещё ~0,5 с на 1000 узлов** (релиз, первый раз
  для графа): решётка (`vault_graph::Grid`, от 500 узлов) отсекает только
  дальние пары, а радиус отталкивания — четыре ребра, и в компактном графе
  соседей много (в начале раскладки все узлы в одной клетке). Результат
  нарочно бит в бит прежний. Повторно тот же граф — из кэша
  (`Layouts`, 32 последних, по хэшу показанного графа). Как ускорить
  дальше: другая модель (Барнс — Хат, меньший радиус, начальная раскладка
  шире) — картинка графа изменится, решать с пользователем.
- **Версия заметки с `#vault-graph` — это граф**: проверка версии (опрос
  клиента, прогрев) строит индекс ссылок, фильтрует граф и берёт раскладку
  (из кэша). Для сотен заметок — миллисекунды; правка ссылок — новая
  раскладка (секунды у тысяч узлов) уже при проверке версии.
- **Данные хранилища для заметок — один поставщик** (граф,
  `vault_data::VaultData`). Отпечаток файла `/_vault/…` по умолчанию — хэш
  его содержимого: проверка версии заметки заново считает ответ. Дешёвый
  признак свежести поставщик может задать сам (`DataProvider::token`).
  Новые данные (теги, обратные ссылки, список папки) — поставщиком и
  функцией в `baluk/`.
- **Фильтр графа в пути файла** (`/_vault/graph/<JSON>.json`, `/` и `%`
  экранируются вручную в `graph.typ`): длинный фильтр — длинное имя; имя
  `_vault` в корне хранилища занято. Как закрыть: не нужно, пока фильтр
  маленький.
- **Подписи графа на картинке Typst мельчают у большого графа** (единица
  раскладки ужимается под `width`), живой граф в приложении — нет.
- **Переставленные руками узлы не запоминаются**: смена фильтра или
  перезагрузка — раскладка заново. Как закрыть: координаты в localStorage
  по id узла (как фильтры).
- **Решётка физики — клетка по самому большому узлу** (`graph-physics.ts`,
  `nearPairs`, с 200 узлов): одна очень длинная подпись делает клетки
  крупными и возвращает почти полный перебор. Пары, наехавшие уже по ходу
  шага (узел сдвинули соседи), решётка видит со следующего кадра —
  перебором они раздвигались в том же. До 200 узлов — прежний перебор,
  движение то же. 1000 узлов: шаг 6,5 → 1,2 мс.
- **Физика графа — не силы ядра**: пружины к местам раскладки вместо
  отталкивания всех со всеми (иначе нетронутый граф поплыл бы — раскладка
  ядра не их точное равновесие). Протянутый узел не расталкивает дальние
  несвязанные узлы — только наехавшие. Как закрыть, если захочется
  «живее»: ядро отдаёт точное равновесие своих сил (без раздвигания), а
  подписи раздвигает клиент.
- **Подписи на экране крупнее раскладки ядра** (телефон, отдаление): узлы,
  чьи подписи наезжают уже в покое, раздвигаются по ужатым размерам —
  перетаскивание рядом может оставить их подписи наложенными, как и на
  картинке без движения.
- **После перетаскивания граф возвращается лишь на четверть** (так
  решили с пользователем: полный возврат пружинами «встряхивал» граф):
  соседи остаются почти там, куда их утянуло. Вернуть картинку ядра — кнопка
  ↶ на `/graph` (плавный переезд, 0,5 с); на главной и в заметках кнопки нет
  — там раскладку возвращает перезагрузка.
- **Без движения (`prefers-reduced-motion`) соседи за узлом не тянутся** —
  двигается только сам узел; переходы и появление — мгновенные.
- **Ширина подписи узла — по числу знаков** (без замера шрифтом), поэтому
  раскладка одинакова везде; у очень широких или узких букв зазоры
  неточные. На телефоне граф вписывается мелко: подписи не мельче 8 px, при
  сильном отдалении видны только книги и найденное.
- **Касание узла на телефоне сразу открывает заметку**: наведения нет, и
  соседи узла подсвечиваются только на широком экране. Как закрыть: первое
  касание — подсветка, второе — переход.
- **Прерванная сборка продолжается на сервере**: ушли с книги, которая
  собирается, — сборка всё равно доработает (Typst не умеет отменять) и
  занимает процессор; следующая заметка её уже не ждёт (сборки
  параллельны). Плюс — возврат к книге потом мгновенный. Как закрыть:
  отмена сборки.
- **Статический сайт: поиск — копия поиска ядра на TS**
  (`app/src/lib/site-search.ts` повторяет `notes-core::search` строка в
  строку). Две реализации могут разойтись. Сверка есть: эталон ядра
  `tests/snapshots/search.json` (`cargo test --test search_parity`) — Vitest
  требует от клиента тех же ответов; правишь поиск ядра — обнови эталон.
  Как закрыть: поиск ядра в WASM (тяжелее) или индекс с готовыми ответами.
- **Индекс поиска сайта — весь текст заметок одним файлом**
  (`assets/data/search.js`, для `tests/vault` 46 КБ): грузится при первом
  открытии поиска. Для хранилища с «Матаном» — мегабайты. Как закрыть:
  индекс по словам (без текста) и фрагменты — по разделам, по требованию.
- **Граф сайта — без фильтров** (папки, тег, ненаписанные, соседи
  заметки): их раскладывает ядро, а сайт статический — граф всего
  хранилища разложен при сборке. Как закрыть: заранее разложить графы
  фильтров (соседи каждой заметки — по файлу) или раскладка в браузере.
- **Данные сайта — JS, а не JSON** (`window.balukData[…] = …`): с `file://`
  браузер не даёт `fetch` читать файлы, а `<script src>` — даёт. На
  веб-сервере JSON был бы чище. Как закрыть: не нужно, пока сайт должен
  открываться с диска.
- **Оглавление сайта — всегда два уровня** (настроек у сайта нет).
- **HTML заголовка для оглавления — вырезается из текста страницы**
  (`passes/heading_html.rs`), а не берётся из дерева: `typst-html` не
  умеет сериализовать отдельный элемент. Опирается на вид разметки
  (`<hN … id="…">…</hN>`, номер — `span.k-num` без вложенных `span`);
  ссылки внутри заголовка разворачиваются в текст, `id` убираются, а
  заголовок с рисунком (SVG) остаётся текстом. Чем грозит: смена формата
  при обновлении Typst — оглавление молча вернётся к тексту (не сломается).
  Как закрыть: сериализация поддерева в `render.rs`, если Typst её откроет.
- **Опрос версии остался запасным**: без событий (сервер не следит за
  файлами, разрыв соединения) клиент опрашивает раз в N секунд
  (`refresh.interval`), как раньше; `refresh.interval = 0` выключает и
  события — только кнопка. Одна вкладка — одно соединение `EventSource` (у браузера
  предел ~6 соединений на сервер по HTTP/1.1: седьмая вкладка будет ждать).

- **Разбор формул интерактивных рисунков написан дважды** — в Typst
  (`baluk/plots.typ`) и в TypeScript (`app/src/lib/plot/`). Расхождение
  ловит сверка на наборе формул (фикстура `Рисунки/Интерактив`, Vitest), но
  только для формул из набора. Как закрыть: считать в клиенте через
  Typst-в-WASM или отдавать сервером точки — дороже; пока — дописывать набор.
- **Подмножество формул узкое**: нет `if`, `calc.max/min`, пользовательских
  функций, параметрических кривых. Для рисунка целиком от параметра есть
  `frames` (кадры считает Typst); живой график с такими формулами — только
  расширением разборщика в обоих местах.
- **Размер кадров не выравнивается сам**: CeTZ подгоняет холст под
  нарисованное, и без невидимой рамки кадры разного размера смещаются.
  Как закрыть: в `frames` мерить кадры (`measure`) и дополнять до общего
  размера — но смещение начала координат так не исправить; пока — рамка
  руками (README).
- **Кадры в PDF — один ряд** (`frames(…, pdf: (1, 4, 8))`, `in-row`): ряд
  не переносится на следующую строку, широкие кадры вылезут за поле; кадры
  выбираются номером, а не значением параметра. Как закрыть: сетка с
  переносом (`columns:`), если понадобится много кадров.
- **Диапазон y/z по умолчанию — по кадру при значениях по умолчанию**: при
  другом значении параметра кривая уходит за поле. Лучше задавать `y:`/`z:`
  явно (README baluk).
- **3D — ортогональная проекция и алгоритм художника по центрам граней**:
  у сильно изогнутых поверхностей возможны огрехи перекрытия; нет осей с
  делениями у поверхности. Как закрыть: z-буфер в WebGL — если понадобится.
- **Вращение пальцем занимает жест на холсте** (`touch-action: none`):
  прокрутить страницу, начав с поверхности, нельзя. У 2D — `pan-y`,
  координаты касанием.
- **Демо интерактивных рисунков в `data/vault`** (раздел в «Возможности/
  Рисунки», два рисунка в «Интеграле Эйлера–Пуассона») — вне git: переданы
  вставками в описании PR.

## Хранилище

- **Хранилище-витрина живёт в `data/vault`, вне git** (как и положено данным
  пользователя). Потеря каталога — потеря витрины; тестовые фикстуры — в
  `tests/vault`. Как закрыть: синхронизация и история заметок (M5).

## Инструменты

- **Прогрев e2e — +20 с к прогону** (`e2e/global-setup.ts` собирает все
  19 заметок до сценариев): ради коротких ожиданий (10 с) и без ложных
  падений по тайм-ауту. Долгую первую сборку `01-switch` проверяет, дописав
  комментарий в файл заметки (кэш устаревает): проверяется повторная
  сборка, а не самая первая — для заглушки это одно и то же. Как закрыть,
  если прогон станет долгим: общий кэш на диске между прогонами (без
  `rm -rf tests/.data/e2e` — кэш годен, пока не менялся код отрисовки ядра).
- **`tools/check.sh` — последовательно и целиком** (~5 мин с e2e): шаги не
  параллелятся, `cargo test` и `clippy` собирают каждый своё. Шаг
  `api-types` сверяет типы с рабочим деревом git: выгруженные, но не
  закоммиченные типы — тоже «упал» (так задумано: коммитить вместе с Rust).
- **Подсказки клавиш прячутся по `(pointer: coarse)`**: на планшете с
  клавиатурой их тоже не будет (палитра, команды). Как закрыть — по
  отзывам: переключатель в настройках.
- **На телефоне вкладки только прокручиваются** — без свайпа между ними и
  без меню «все вкладки». Для Android (M4) — продумать заново.
- **`tools/shot.mjs` не эмулирует телефон** (`mobile: false`): с эмуляцией
  Chromium масштабирует окно и замеры врут. Узкую вёрстку проверяем шириной.
