## Итерация: «кадры» CeTZ с ползунком (M3) — сделано (ветка `frames`)

Пользователь (2026-09-26): выбрал кадры (а не Tauri); перед началом —
`cargo clean` (`target/` разросся до 48 ГБ).

Идея: любой рисунок `canvas` с параметром. Typst собирает его для каждого
значения; в приложении ползунок переключает готовые кадры, «▶» проигрывает
их по очереди (анимация, шаги алгоритма). Всё считает Typst — второго
разборщика нет, стиль библиотеки сохраняется целиком.

Решения по умолчанию (без вопросов пользователю; поменять — легко):
- Синтаксис: `frames(n => canvas(theme => { … }), n: (from: 1, to: 20, step: 1,
  value: 5))` — одна переменная; имя параметра — ключ словаря, значения —
  `from/to/step` или явный массив `values: (…)`. Подпись значения под рисунком.
- Предел — 60 кадров на рисунок (больше — ошибка сборки с объяснением).
- HTML: `div.k-frames` с `data-k-frames` (JSON: имя, значения, номер по
  умолчанию, скорость `fps`) и N обычных `canvas` (`div.k-frame` — ядро
  склеит темы и глифы как обычно). Без JS CSS показывает только кадр по
  умолчанию (`[data-k-frame-default]`) — статический сайт и PDF-логика те же.
- PDF: кадр по умолчанию + мелкая подпись «n = 5» (как у `interactive-plot`);
  опция `pdf: "strip"` — несколько кадров в ряд — только если просто.
- Клиент: компонент `Frames.svelte` (монтируется в `NoteView` как `Plot`):
  ползунок по номеру кадра, значение, «▶/❚❚», клавиши ←/→ на фокусе;
  переключение — `hidden` у кадров (без перерисовки).
- Демо: карточки `data/vault` (суммы Римана в «Интеграле Эйлера–Пуассона»
  или отдельная карточка; раздел в «Возможности/Рисунки»). «Матан» не трогать.
