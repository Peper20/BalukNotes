## Ядро на устройстве, сервер — хранилище

Решение пользователя (2026-09-27, вместо «клиенты тонкие» от 2026-09-26):
Typst компилирует клиент, сервер в сети только хранит файлы,
синхронизирует и пускает по сессии — VPS слабый (1 ядро, 2 ГБ). Как
устроено — `docs/architecture.md`, §1 и §9. Нынешний `notes serve` с
браузером — уже «ядро на устройстве» для компьютера.

Приоритет — **десктоп** (M5): заметки пишутся на компьютере (Claude Code),
остальные устройства почти всегда читают. Десктоп работает и без сервера
(хранилище на диске), синхронизация подключится, когда будет M4.
Исследование E4 (WASM) — до начала M7.

## Настройки устройства — до M5–M6

Решение пользователя (2026-09-27): что допустимо на компьютере, на
телефоне недопустимо, поэтому настройки производительности у каждого
устройства свои, со своими значениями по умолчанию.

- [ ] Схема настроек: признак «настройка устройства» (не синхронизируется)
      и значения по умолчанию по платформе (компьютер / телефон). Вид
      (тема, кегль…) — общий
- [ ] Прогрев — настройка: «всё хранилище» / «только открытое» /
      «выключен». По умолчанию: компьютер — всё хранилище, телефон —
      выключен (принудительный прогрев на телефоне недопустим).
      Прогрев на компьютере — бережно: одна сборка в одном потоке (темы
      по очереди, а не параллельно), пониженный приоритет, после прохода —
      освободить память Typst (`comemo::evict`); собранное не собирается
      снова, дальше — только изменившееся. Порядок прогрева — прежний
- [ ] Сборок одновременно — настройка, по умолчанию 2 (сейчас — половина
      ядер, не меньше двух)
- [ ] Пределы кэша — настройки (сейчас константы): страницы в памяти
      64 МБ, кэш на диске 512 МБ, срок чужих записей 14 дней; для
      телефона — меньше (подобрать замером в M6)
- [ ] Память Typst — сколько сборок помнить рисунки (`comemo::evict(N)`,
      сейчас 10) — настройка: компьютер — 10, телефон — меньше (замер в M6)

## M4. Сервер-хранилище и вход

- [ ] Вход вместо общего токена: `POST /api/login` (пароль) → сессия в
      cookie `HttpOnly`, `SameSite=Strict` (за HTTPS — `Secure`); срок
      сессии скользящий — 30 дней без обращений (параметр сервера), любое
      обращение продлевает, истёк — вход заново; токен один
      (сессионный), без refresh-токена. Сессии переживают перезапуск:
      сервер хранит на диске хэши токенов (сам токен — только у
      устройства); позже — KV-база (выбрать);
      `POST /api/logout`. Токен в адресе (`?token=`) не принимать никогда.
      Перебор пароля замедлять (пауза после неудачи). Экран входа в
      клиенте — по ответу 401 (вид — варианты на выбор пользователю)
- [ ] **Хранилище с сервера — недоверенное**: Typst в HTML-экспорте
      может выдать любой элемент и атрибут (`html.elem("img", attrs:
      (onerror: …))` — проверено), а клиент вставляет HTML заметки через
      `innerHTML`: чужая заметка исполнила бы свой JS на всех устройствах.
      До синхронизации — обязательно: ядро пропускает в HTML заметки только
      разрешённые теги и атрибуты (без `script`, `on*`, `javascript:`,
      `iframe`…; список — по тому, что выдаёт `baluk`), клиент — строгий
      CSP (`script-src 'self'`). Своего JS у заметок нет: интерактив —
      только живые блоки из реестра клиента
- [ ] Пределы сборки (решено пользователем): лимит времени и памяти на
      сборку заметки — зависшая или прожорливая заметка даёт ошибку, а не
      вешает устройство; пакеты Typst — только из белого списка (CeTZ…)
      с закреплёнными версиями. Проверка Typst-кода при синхронизации —
      эти же правила. Белый список, версии и пределы регулярно
      пересматривать и расширять: главное — красивые заметки
- [ ] Сервер без Typst: хранилище, версии файлов, события об изменениях,
      сессии — отдельный режим/бинарник, который собирается без
      `typst` (память и размер для VPS)
- [ ] Синхронизация: копия хранилища на устройстве, версии файлов;
      изменения — по событию сервера. Сначала просто: пишет компьютер
      (Claude Code), остальные устройства получают (решено пользователем);
      блокировка на редактирование — задел, когда правки пойдут с
      нескольких устройств
- [ ] HTTPS (сам сервер или обратный прокси — решить), развёртывание на
      VPS службой
- [ ] Клиент: понятный экран «нет связи с сервером» / «нужен вход»

## Решения пользователя, которые держат ограничения

- Параметры движения графа (`RETURN = 0.25`, `DAMPING = 0.3` в
  `graph-physics.ts`) подобраны пользователем: после перетаскивания соседи
  возвращаются на четверть пути. Не менять без него; станут значениями
  по умолчанию ползунков (M3).
- Префикс `k-` в классах и переменных — оставить.
- Имя библиотеки `baluk` — оставить (сменить легко). Переводчик старого
  русского API не храним: импорт старых конспектов — отдельным инструментом.
- Панель кадров — «тихий» вид (контурные значки без фона и рамки).
- Typst компилирует клиент; сервер в сети — без Typst (см. выше).
- Белый список пакетов Typst, их версии и пределы сборки — не догма:
  пересматривать регулярно и расширять, если заметкам нужно (красота
  заметок важнее).
- Не отдавать облачным сессиям: приложения Tauri, Android, авторизацию,
  замену файлов шрифтов, обновление Typst — нужны пользователь или его
  машина.
