## M4. Сервер-хранилище и вход

- [ ] Вход вместо общего токена (architecture §9): срок сессии - параметр
      сервера; хэши токенов на диске, позже KV-база (выбрать); перебор пароля
      замедлять (пауза после неудачи); экран входа по 401 (вид - варианты на
      выбор)
- [ ] **Хранилище с сервера - недоверенное**: Typst выдаёт любой элемент и
      атрибут (`html.elem("img", attrs: (onerror: ...))` - проверено), клиент
      вставляет HTML через `innerHTML` - чужая заметка исполнила бы свой JS на
      всех устройствах. До синхронизации обязательно: ядро пропускает только
      разрешённые теги и атрибуты (без `script`, `on*`, `javascript:`,
      `iframe`...; список - по тому, что выдаёт `baluk`), клиент - строгий CSP
      (`script-src 'self'`). Своего JS у заметок нет
- [ ] Пределы сборки (решение пользователя): лимит времени и памяти - зависшая
      заметка даёт ошибку, а не вешает устройство; пакеты Typst - белый список
      (CeTZ...) с версиями; те же правила - при синхронизации. Список, версии и
      пределы регулярно пересматривать и расширять: красота заметок важнее
- [ ] Сервер без Typst: хранилище, версии файлов, события, сессии - режим или
      бинарник, собираемый без `typst`
- [ ] Синхронизация: копия на устройстве, версии файлов, изменения по событию;
      сначала пишет компьютер, остальные получают (решение пользователя);
      блокировка - задел
- [ ] HTTPS (сам сервер или обратный прокси - решить), служба на VPS
- [ ] Клиент: понятный экран "нет связи с сервером" / "нужен вход"
