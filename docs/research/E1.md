# E1. One text compilation for all themes

**Question** (tech debt "Every theme is a full compilation"): a note is built
once per theme (two now: `classic`, `night`), although the text is the same
and only the figures differ. Is it worth compiling the text once and the
figures per theme?

**Conclusion: it is not.** Almost all build time is CeTZ figures (95-99 % for
notes with figures), and they have to be built per theme anyway. Text without
figures builds fast and already in parallel per theme: the wait time gain is
hundredths of a second, the CPU gain is up to a half only for a book with no
figures at all. No code.

## Method

- Release build, 4 cores (Intel Xeon 2.8 GHz), Typst 0.15.1.
- A temporary example in `notes-core`: `Compiler::compile_html` directly,
  without the page cache; `comemo::evict(0)` before every measurement (from
  scratch), except the row "the second theme after the first". The best of
  three; CPU - process time from `/proc/self/stat` (all threads).
- "Without figures" - a copy of the library where `canvas` returns empty
  content: text, formulas, blocks, the template remain - what "one text
  compilation" would save.
- Notes: `Книга` and `демо/*` from `tests/vault`; synthetic ones (the cloud
  has no "Матан"): `synth/текст` - a book of 170 KB of source (12 chapters x 8
  sections, paragraphs with formulas, definitions, theorems, display
  formulas, **no figures**); `synth/рисунки` - 4 chapters x 6 sections with
  two figures each (a plot with a fill and a surface).

## Numbers

Wait time, s (CPU, s, in parentheses):

| Note | 2 themes in parallel (now) | 1 theme | 2nd theme right after the 1st | 2 themes without figures |
|---|---|---|---|---|
| `Книга` | 0.068 (0.10) | 0.062 (0.05) | 0.056 | 0.047 (0.08) |
| `демо/визуализация` | 6.99 (11.90) | 4.60 (4.57) | 5.40 | 0.075 (0.14) |
| `демо/компоненты` | 2.97 (4.78) | 1.72 (1.71) | 2.31 | 0.098 (0.18) |
| `synth/текст` | 0.93 (1.77) | 0.85 (0.85) | 0.66 | 0.65 (1.24) |
| `synth/рисунки` | 3.75 (6.37) | 2.41 (2.40) | 3.04 | 0.135 (0.25) |

The text share (without figures) of the CPU time of two themes:
`визуализация` 1 %, `компоненты` 4 %, `synth/рисунки` 4 %; for `synth/текст`
all of the time. Repeats vary by up to +-30 % on short measurements
(`synth/текст` 0.93 and 0.65 s for the same work).

## What it means

- "Text once" would save one of two **text** compilations: for notes with
  figures - up to 4 % of CPU and ~0 of wait time (the themes run in parallel
  anyway); for a book without figures - ~0.6-0.9 s of CPU per 170 KB of
  source, but the same ~0.1 s of wait time.
- Figures differ per theme not only in colors (derived colors `lighten`,
  `transparentize`, the shape per theme - the fixture "Темы и градиент"), so
  they have to be built once per theme anyway. And figures inside Typst are
  part of the same document (counters, state, theme): they cannot be built
  separately from the text without support in Typst.
- The Typst memo already shares common work between themes if they are built
  in turn (`synth/текст`: the 2nd theme 0.66 s instead of 0.85), but two
  themes in turn take longer than in parallel.
- Parallel themes cost the CPU more than the sum (`визуализация`: 11.9 s
  against 2 x 4.6) - the threads interfere; by wait time parallel is still
  better (7.0 s against ~10 s in turn).

## An option for the future

On a phone (M6, one or two slow cores) parallelism will not help: there it
pays to build first the theme being read and the second one after showing
(lazy theme merging, roadmap M6).
