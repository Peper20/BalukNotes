# E7 - Desktop on Tauri 2 (Linux)

The task (roadmap M5): before the desktop code, check that a Tauri window does
not spoil rendering and that the `app/` interface works with the core in the
same process through its own address scheme (architecture §1), without a port
or a token.

## Method

- A laptop i5-13420H, Arch, KDE Plasma 6 (Wayland), hybrid graphics Intel +
  NVIDIA. WebKitGTK 2.52.6 (`webkit2gtk-4.1`), Chromium 153, Tauri 2.12 (wry
  0.57).
- Rendering: the same 11 pages of the "Демо" vault (notes, a book, code,
  figures, interactivity, 3D, the graph; light and dark scheme) from `notes
  serve`, 1300x2400 screenshots in Chromium (Playwright) and in the system
  WebKitGTK (python `gi`, `WebKit2.WebView.get_snapshot`). On every page - a
  probe: the number of formulas and SVG, zero-height formulas, loaded and
  failed fonts, page errors and CSP violations. Then the computed styles of
  lines.
- The window: a prototype (a `notes-desktop` binary in the workspace, not in
  git). The Tauri window opens `notes://localhost/...`, the
  `register_asynchronous_uri_scheme_protocol` handler turns a request into
  `notes_server::router(state).oneshot(...)` (the same `AppState` as
  `notes serve`: `VaultSet::registry`, warm-up, watcher). A copy of
  `tests/vault`, a script in the window walks 10 pages and sends the result
  back by a scheme request.

## Rendering: WebKitGTK against Chromium

The structure is the same on all pages: the same number of formulas, SVG and
canvases, no zero-height formulas, the same fonts loaded, no failed fonts, no
page errors. Formula heights match within 0.1 px. Differences:

- **Text lines are lower by a fraction of a pixel**: WebKit rounds the line
  height to a whole pixel (`line-height` 26.22 px -> a 26 px line, in code
  22.8 -> 22). The page is 1-2 % shorter, almost invisible by eye.
- **No thin gap after ∑ and ∫ with limits**: `∑_(i=1)^n f` in WebKit comes out
  solid (`i=1f`), in Chromium (and in PDF) there is a gap between them. It
  seems WebKit gives no `rspace` to an operator with limits. A fix - an
  explicit gap in the formula pass (check against the PDF).
- **`<select>` is GTK-styled**: it is wider, so the `/graph` filter row at a
  width of 1300 px moves "15 узлов · 33 связи" to a second line.
- The `→` arrow in the breadcrumbs comes from another fallback font (the
  interface only, notes are not affected).

Conclusion: rendering does not block M5. Fix the above in M5.

## The Tauri window: the address scheme

- **The interface works fully**: client files, the API, themes, font parts,
  the graph. 10 pages of `tests/vault` (formulas, a book, interactivity,
  frames, fallback fonts, a build error, the graph) are ready
  (`data-state="ready"`), no errors or CSP violations (`script-src 'self'`
  etc.).
- **Requests with a body get through** (POST, PUT JSON). Tauri for Linux
  enables `linux-body` of wry.
- **Response compression must be removed**: the handler drops
  `Accept-Encoding` from the request, otherwise a compressed response goes
  into the scheme (whether WebKit decompresses it was not checked, inside one
  process compression is not needed).
- **SSE through the scheme does not work**: the handler answers only whole
  (wry puts the body into a `MemoryInputStream`). `EventSource` gets `hello`,
  the stream closes, the browser reconnects every ~3 s, and every time the
  client fetches the note and folder lists again (60 connections and 240
  requests in 3 minutes).
- **Long polling through the scheme works**: a request waiting 30 s for an
  answer - six at once, fast requests pass alongside; a 125 s request is not
  cut off. The SSE replacement is `GET .../events?after=<seq>`, an answer on a
  change or an empty one after ~25 s. It is plain HTTP: the same way suits the
  browser, Android and the WASM worker (M7), no separate API over Tauri IPC is
  needed.
- **The window on Wayland with NVIDIA** renders on the GPU without workarounds
  (`WEBKIT_DISABLE_DMABUF_RENDERER` was not needed). A hidden window without
  GL (`Gtk.OffscreenWindow`) crashes WebKit - this concerns only screenshots,
  not the app.
- The window icon is the generic Wayland icon: a `.desktop` with the app id
  is needed.

## What to take into M5

- The scheme handler (the essence of the prototype):

  ```rust
  .register_asynchronous_uri_scheme_protocol("notes", move |_ctx, request, responder| {
      let router = router.clone();
      tauri::async_runtime::spawn(async move {
          let (mut parts, body) = request.into_parts();
          parts.headers.remove(http::header::ACCEPT_ENCODING);
          let req = axum::extract::Request::from_parts(parts, axum::body::Body::from(body));
          let (parts, body) = router.oneshot(req).await.expect("infallible").into_parts();
          let bytes = body.collect().await.map(|b| b.to_bytes()).unwrap_or_default();
          responder.respond(http::Response::from_parts(parts, bytes.to_vec()));
      });
  })
  ```

- Events by long polling (see above).
- The window: `WebviewUrl::CustomProtocol("notes://localhost/")`. On Windows
  and Android the scheme address differs (`http://notes.localhost/`), the
  client knows only relative paths, so this does not matter.
- Starting the core (`warm_fonts`, `start_background`, closing idle vaults)
  repeats `notes_server::serve`: move it into a shared server function.
- Fix the WebKit differences (the gap at ∑ and ∫, the graph filter row).
