# E2. A CeTZ figure cache by source

**Question** (tech debt "The first build of a large book takes seconds"):
after a chapter edit the book is rebuilt whole, and almost all the time goes
to CeTZ figures. Is a figure cache by their source needed?

**Conclusion: within one run it already exists - the Typst memo (`comemo`).**
A text edit in a note with figures rebuilds it in 0.05-0.17 s instead of
2.6-6.8 s: unchanged figures come from the memo. Our own figure cache would
be needed only after a restart (and the disk page cache serves unchanged notes
anyway) and after 10+ builds of other notes (the memo is evicted). No code:
our own disk figure cache would require replacing the `html.frame` layout
inside Typst; an option is to evict the memo more gently (tech debt).

## Method

- Release build, 4 cores, Typst 0.15.1; `Compiler::compile_html` directly
  (as a note build on the server, both themes in parallel, after a build -
  `comemo::evict(10)`, as in `world.rs`). The best of three.
- An edit is a write to a vault file between two builds without resetting the
  memo (the server does the same after a file is saved). "From scratch" -
  after `comemo::evict(0)`.
- Notes: `демо/визуализация` (various figures: 2D, 3D, graphs, arrays),
  `демо/компоненты`, the synthetic `synth/рисунки` (48 figures, see E1).

## Numbers

Rebuild time, s:

| Edit | `synth/рисунки` | `демо/визуализация` | `демо/компоненты` |
|---|---|---|---|
| from scratch (empty memo) | 3.42 | 6.85 | 2.58 |
| no edits | 0.04 | 0.08 | 0.04 |
| a paragraph at the end | 0.10 | 0.10 | 0.05 |
| a paragraph at the start | 0.10 | 0.10 | 0.04 |
| a new section at the start (numbers shift) | 0.15 | 0.15 | 0.11 |
| one figure changed | 0.98 | 1.34 | - |

How long the memo lives: a text edit in `демо/визуализация` after N builds of
other notes (`Книга`, `synth/текст`, `демо/компоненты` in a loop):

| N | 0 | 5 | 9 | 10 | 12 | 20 |
|---|---|---|---|---|---|---|
| rebuild, s | 0.11 | 2.81 | 0.35 | 6.97 | 7.02 | 6.47 |
| process memory, MB | 839 | 1391 | 1405 | 1405 | 1427 | 1427 |

(N = 5 is an outlier: part of the memo entries was evicted early; not
repeated.) After 10 builds of other notes the figure memo is evicted
entirely - as from scratch.

## What it means

- The scenario "write a chapter, save, look" is already fast: the server
  rebuilds one note, the figure memo is alive, a rebuild takes tenths of a
  second.
- It is slow: (1) on the first build after a server start if the note changed
  while it was not running (otherwise the disk page cache serves it); (2) if
  between edits the server built 10+ other notes (a warm-up after a mass edit,
  `git pull`).
- Our own disk figure cache by source would cover these cases too, but a
  figure's key is not only its text: theme, font size, fonts, document state
  (counters inside captions, `current-theme`). Typst computes this key itself
  (the memo), and a ready SVG can replace the `html.frame` layout only with
  our own figure layout - that means giving up CeTZ-through-Typst.
- The memo is expensive in memory: +0.6 GB for four heavy notes (release).
  Keeping it longer (e.g. `evict(30)`) keeps fast rebuilds alive longer at the
  cost of memory; decide together with the server memory limits (M5, many
  users).
