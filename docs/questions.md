## Память сервера: как вернуть системе

Разбор ~575 МБ (`docs/research/E5.md`): живого в куче после релиза ~72 МБ
(после правки `comemo` в этом PR), остальное - память, которую glibc не
возвращает системе. Дочерний процесс для сборки не нужен. Варианты (RSS в
простое, `tests/vault`):

1. **jemalloc** (`tikv-jemallocator`, только бинарник `notes`) - ~270 МБ, пик
   прогрева 450 вместо 630, скорость та же; без `unsafe` в нашем коде. Минус -
   C-библиотека в сборке; под Windows (MSVC) не собирается - там остаётся
   системный аллокатор. **Фаворит.**
2. **`malloc_trim(0)` после релиза по простою** (glibc, Linux) - ~250 МБ; с
   `MALLOC_ARENA_MAX=2` (настройка аллокатора при запуске) - ~170 МБ. Нужен
   один `unsafe` вызов: в workspace `unsafe_code = "forbid"`, придётся
   ослабить до `deny` с разрешением в одном месте.
3. Оставить как есть (~520-560 МБ).

По умолчанию сейчас - 3 (ничего не выбрано). После выбора - автозапуск
`notes serve` (служба systemd пользователя).
