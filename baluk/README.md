# baluk — библиотека оформления BalukNotes

Библиотека Typst, которой оформлены заметки и конспекты BalukNotes: один
исходник даёт и страницу в приложении (HTML), и PDF. Имена функций и
параметров — английские; текст заметок пишется на любом языке.

Правила содержания (что писать и как проверять) — в `CLAUDE.md` в корне проекта.
Здесь только о том, как пользоваться библиотекой.

Проверено на Typst 0.15.1. Единственная внешняя зависимость — `@preview/cetz:0.4.2`
(лежит в кэше `~/.cache/typst/packages`, работает офлайн).

## В приложении заметок

Библиотека видна хранилищу как `/_baluk/` (виртуально — копии в
хранилище нет). Тема приходит входом `theme` (`--input theme=night`), в
документе её указывать не нужно.

**Заметка** — один файл, одна тема целиком; `=` — раздел, нумерация сквозная
(«Определение 3», «Рис. 2»), номера разделов по умолчанию скрыты:

```typst
#import "/_baluk/lib.typ": *
#show: note.with(title: [SSH], tags: ("сеть", "безопасность"))

#lead[…]
= Как это работает
```

**Книга** — папка с `main.typ`: `=` — глава с «Главой N», нумерация «глава.n».

```typst
#import "/_baluk/lib.typ": *
#show: book.with(
  kind: auto,                    // надпись над названием: auto — «Конспект»; [Задачник], [Шпаргалка]…
  title: [Кратные интегралы],
  subtitle: [Двойные, тройные и $n$-мерные интегралы],
  author: [Математический анализ · 2 семестр],
  date: [2026],
  description: [Для кого конспект и как его читать — 2–3 фразы на титул.],
  title-page: true, toc: true, depth: 2,   // только PDF
)
#include "01-повторение.typ"
```

Главы книги начинаются с `#import "/_baluk/lib.typ": *`.

**Язык заметки** — `lang:` у `note` и `book` (по умолчанию `"ru"`). От него
зависят слова оформления («Определение»/«Definition», «Рис.»/«Fig.»,
«Глава»/«Chapter», «Конспект»/«Notes», подпись кадров), переносы и кавычки;
в HTML — атрибут `lang` у `<article>`. Словари — `i18n.typ` (сейчас `ru` и
`en`; языка нет в словаре — русские слова, `notes check` предупреждает).
Свои слова — `words:` поверх словаря языка (ключи — как в `i18n.typ`; чего
нет в `words:`, берётся из словаря). Сообщения об ошибках библиотеки всегда
по-русски.

```typst
#show: note.with(lang: "en", title: [Limits])
#definition[…]   // «Definition 1.»

#show: note.with(lang: "de", words: (definition: "Definition", figure: "Abb."), title: […])
```

**Ссылки между заметками** — путь от корня хранилища без `.typ`, якорь — текст
заголовка или метка. Приложение проверяет и заметку, и раздел (`notes check`):

```typst
#see("Сеть/UFW")                               // «UFW»
#see("Сеть/SSH", anchor: "Смена порта")        // «Смена порта»
#see("Сеть/SSH", anchor: "Смена порта")[порт]  // своя надпись
```

## HTML и PDF

Один исходник — два вида. В HTML (`target() == "html"`) каждый блок выдаёт
разметку с классами `k-…`, вид задаёт `app/src/baluk-css/`, сборка — `assets/baluk.css`; рисунки — SVG
(`div.k-frame`), по варианту на тему. Правила для правок библиотеки — в
`CLAUDE.md` корня репозитория, раздел «Библиотека».

## Темы

| Тема | Название | Характер |
|---|---|---|
| `classic` | Классика | синий акцент, врезки с полосой, книжный абзац |
| `night` | Ночь | **та же вёрстка, другая палитра**: тёмная страница для чтения с экрана |

`night` получена из `classic` одним `customize(classic, (color: …))`: шрифты,
кегли, поля, заголовки, врезки и колонтитулы у них общие. Один конспект в двух
видах должен выглядеть одним конспектом. `title` — название темы в интерфейсе
приложения.

Своя тема — глубокое слияние с существующей, указывать только то, что меняется:

```typst
#let mine = customize(themes.classic, (
  name: "mine", title: "Моя",
  color: (accent: rgb("#7a1f5c"), fig: (line: rgb("#7a1f5c"))),
  size: (text: 11.5pt),
))
#show: book.with(theme: mine, ...)   // или новая запись в `themes` — появится в приложении
```

Устройство темы (палитра, шрифты, кегли, поля) — в `theme.typ`. Вёрстка одна на
все темы, поэтому своя тема — это только палитра.

Текущая тема в своём коде — `current-theme()` (только внутри `context`); в
`canvas(theme => …)` она приходит аргументом.

## Блоки (`blocks.typ`)

| Вызов | Что это |
|---|---|
| `#definition(title: "…")[…]` | определение; нумеруется «глава.n», вместе с теоремами |
| `#theorem(title: "…")[…]` | теорема / утверждение |
| `#proof[…]` | эскиз доказательства, мельче, с ∎ |
| `#example(title: "…")[…]` | разобранный пример; нумеруется отдельно |
| `#step[Название]` | внутри примера: «Шаг 1. Название.», своя нумерация в каждом примере |
| `#answer[…]` | ответ в рамке, прижат вправо |
| `#remark[…]`, `#idea[…]`, `#algorithm[…]`, `#pitfall[…]` | ненумерованные врезки |
| `#formula(label: "…")[$ … $]` | ключевая формула в рамке — одна-две на раздел |
| `#lead[…]` | 2–4 вводных предложения главы |
| `#plan([…], […], […])` | «В этой главе»: что научимся делать |
| `#summary([…], […])` | «Коротко о главном» в конце главы |
| `#quiz(([вопрос], [ответ]), …)` | «Проверь себя», ответы мелко внизу блока |
| `#pitfalls(([ошибка], [как избежать]), …)` | таблица типичных ошибок ✗/✓ |
| `#data-table(cols, header: (…), highlight: ("4,*": "third"), …cells)` | таблица с подсветкой клеток, строк («4,\*») и столбцов («\*,2») — трассировки алгоритмов |
| `#margin-note[…]` | мелкая заметка сбоку от мысли |
| `#side-by-side[текст][рисунок]` | текст и небольшой рисунок рядом, в две колонки |
| `#small-caps[…]` | капитель для кириллицы (у шрифтов нет своей, `smallcaps` не работает) |

Определения и теоремы не рвутся между страницами. Примеры рвутся.

## Код (`code.typ`)

```typst
#listing(
  caption: [построение P],
  highlight: (5, 6),              // подсветить строки
  callouts: ("5": 1, "12": 2),    // кружки ① ② у строк
  complexity: [$O(n m)$],
  ```cpp
  ...
  ```,
)
Строка #callout(1) — формула построения.   // ссылка на кружок из текста

#code-from-file("/code/prefix.cpp", region: "build", highlight: (3,))
```

- Подсветка берётся из цветов темы, лигатуры выключены.
- Листинг до 15 строк не рвётся между страницами.
- `code-from-file` берёт кусок между `// region: имя` и `// endregion: имя`.
  Путь указывается от корня хранилища и начинается с `/`. Нет региона — сборка
  падает с понятной ошибкой.

## Рисунки (`figures.typ` → `figures/`, на cetz 0.4.2)

```typst
#fig(
  canvas(unit: 2.5cm, theme => {       // theme — текущая тема
    import cetz.draw: *
    fill-between(x => x * x, x => x, 0, 1)   // заливка между кривыми
    axes(x: (-0.1, 1.3), y: (-0.1, 1.2))
    plot(x => x * x, 0, 1.08, label: $y = x^2$, label-x: 0.9, label-anchor: "north-west")
    spoke(0.6, 0.36, 0.6)              // двусторонняя стрелка
    tick(1, $1$)
    line((0, 0), (1, 1), stroke: 1pt + theme.color.fig.second)   // свои линии — цветами темы
  }),
  [Подпись — утверждение о том, что видно],
  label: "рис-спица",                  // в тексте: рис. @рис-спица
  floating: false,                     // true — рисунок встанет вверх/вниз страницы
)
```

| Помощник | Назначение |
|---|---|
| `axes`, `tick`, `plot`, `parametric`, `fill-between`, `spoke`, `point` | 2D: оси через начало координат, функции, параметрические кривые, заливки |
| `contours(f, levels, xr:, yr:)` | горизонтали поверхности (marching squares) |
| `p3`, `axes3d`, `surface(f, xr, yr, style: "shaded"/"flat"/"wire")`, `prisms`, `base-shape`, `revolution(r)`, `cross-section(f, y0)` | псевдо-3D, алгоритм художника |
| `array-cells(values, highlight:, spans:, pointers:, block-size:, block-values:, arcs:, index-from:)` | одномерный массив: блоки и своды (sqrt-декомпозиция), дуги (обмен, ссылка), указатели |
| `matrix-cells(matrix, rects:, cells:, arrows:, values:, index-from:)` | матрица и таблица ДП: подсветка клеток и стрелки переходов |
| `graph(vertices, edges, directed:, highlight:, marks:, shape:)` | граф; узлы кругом или прямоугольником (две строки: ключ и приоритет); встречные рёбра разводятся сами |
| `tree-layout(edges, root)`, `binary-layout(children, root)` + `binary-edges(children)`, `circle-layout(names)` | координаты вершин: по уровням, по порядку ключей (деревья поиска, декартовы деревья), по окружности |
| `in-row(…, separators: ($=$, $-$))` | несколько холстов в ряд: кадры алгоритма, формула из картинок |

Ребро `graph` — `(u, v, стиль, подпись, (side: "left", at: 0.5))`: подпись
(вес) — слева или справа от направления u → v (`side`), в доле длины ребра
от u (`at`); по умолчанию — слева, посередине. Если подпись заслоняет
вершина — сменить сторону или сдвинуть `at`.
Стили рёбер `graph`: `"normal"`, `"bold"`, `"second"`, `"dim"`, `"dashed"`;
форма узлов: `"circle"` или `"rect"`.

## Интерактивные рисунки (`plots.typ` → `plots/`)

График с ползунками параметров и поверхность с вращением. Формула — строка
с кодом Typst; в приложении рисунок живой, в PDF и без JS — кадр при
значениях по умолчанию и подпись «a = 1, b = 2».

```typst
#fig(interactive-plot(
  ("a * calc.sin(b * x)", (f: "calc.sin(x)", label: "sin x", dashed: true, color: "second")),
  -5, 5,                                   // x ∈ [a, b]
  params: (a: (from: 0, to: 3, step: 0.1, value: 1), b: (from: 0.5, to: 4, value: 1)),
  y: (-3, 3),                              // лучше задать: иначе — по кадру по умолчанию
  labels: ("x", "y"), width: 8, height: 5, // поле графика, см
), [Подпись])

#fig(interactive-surface("calc.sin(k * x) * calc.cos(y)", (-3, 3), (-3, 3),
  params: (k: (from: 0.2, to: 2, value: 1)), z: (-1, 1),
  n: 24, style: "shaded",                  // или "wire"; color: "face"/"line"/"second"/"third"
  rotation: -30, tilt: 28, size: 3,        // начальный вид (градусы), размер коробки (см)
), [Подпись])
```

- Формула — подмножество Typst: числа (`2.5`, `1e-3`), `x` (и `y` у
  поверхности), параметры, `+ - * /`, скобки, унарный минус, `calc.sin cos
  tan asin acos atan exp ln log sqrt pow abs floor ceil`, `calc.pi`,
  `calc.e`. Степень — `calc.pow(x, 2)`; `asin`/`atan` дают число (радианы),
  а не угол. Минус можно писать без пробелов (`x-1` — это x − 1).
- Вне области определения (деление на ноль, корень из отрицательного) —
  разрыв кривой, не ошибка. Точки по разные стороны от поля — тоже разрыв
  (асимптоты `tan`). Непонятная формула — ошибка сборки с объяснением.
- Разбор и вычисление написаны дважды: `plots/formula.typ` и клиент
  (`app/src/lib/plot/formula.ts`), построчно одинаково. Сверка — фикстура
  `tests/vault/Рисунки/Интерактив.typ` (Vitest читает её снимок).
- Цвета в HTML — переменные `--k-fig-*` (из `css-colors`), клиент рисует ими.

## Кадры (`frames.typ`)

Любой рисунок с параметром: Typst собирает его для каждого значения, в
приложении под рисунком — ползунок, кнопки ‹ › и проигрывание (шаги
алгоритма, сходимость, движение). В PDF и без JS — кадр по умолчанию и
подпись значения; `pdf: (1, 4, 8)` — в PDF эти кадры в ряд.

```typst
#fig(frames(n => canvas(theme => {
  import cetz.draw: *
  rect((-0.1, -0.1), (3.1, 1.2), stroke: none)   // рамка постоянного размера
  …                                              // рисунок при данном n
}), n: (from: 1, to: 12, value: 4)), [Сумма Римана: $n$ прямоугольников])

#fig(frames(k => canvas(…), k: (values: (0, 1, 2, 3)),
  label: k => [проход #k],   // своя подпись; none — без подписи
  fps: 2, loop: false,       // скорость проигрывания, по кругу ли
  pdf: (1, 2, 3, 4),         // в PDF — эти кадры в ряд (номера с 1); auto — кадр по умолчанию
), [Шаги алгоритма])
```

- Параметр — ровно один, именованный: `(from:, to:, step:, value:)` (`step`
  по умолчанию 1) или `(values: (…), value:)`, или просто массив значений.
  Значения — любые: числа, строки, словари состояния алгоритма.
- Подпись по умолчанию — «n = 4» для чисел, «кадр 2 из 5» для прочего (на языке заметки).
- Не больше 60 кадров на рисунок: каждый кадр — свой SVG (~4–8 КБ).
- `pdf:` — номера кадров (с 1, не значения параметра), каждый со своей
  подписью, в ряд через `in-row`; ряд не переносится — широкие кадры
  выберите поменьше. На HTML не влияет.
- Кадры лежат друг на друге: место — по самому большому. Чтобы рисунок не
  «прыгал», рисуйте невидимую рамку постоянного размера (`rect(…, stroke: none)`):
  CeTZ подгоняет холст под нарисованное.

## Граф хранилища (`graph.typ`)

Граф заметок прямо в заметке — весь или по фильтру:

```typst
#vault-graph()                                        // всё хранилище
#vault-graph(around: "Сеть/SSH", depth: 2)            // соседи заметки
#vault-graph(folders: ("Математика",), missing: false, width: 10cm)
#vault-graph(tag: "линал", orphans: false)
```

- `around`, `depth` — только соседи заметки на `depth` шагов; она — в
  центре (обведена), даже если её скрыл бы другой фильтр;
- `folders` / `hidden` — только эти / кроме этих папок верхнего уровня
  (`"в корне"` — заметки в корне хранилища);
- `tag` — только заметки с тегом; `missing` — ненаписанные (на них
  ссылаются, но их нет); `orphans` — заметки без связей;
- `width` — наибольшая ширина рисунка (большой граф ужимается).

Фильтр и раскладку считает приложение (`notes-core::vault_graph`) — те же,
что у страницы графа: заметка читает готовый граф из виртуального файла
`/_vault/graph/<фильтр>.json`. В PDF и в HTML без скрипта граф — картинка
CeTZ; приложение и сайт оживляют его по тем же координатам (наведение,
перетаскивание узлов в рамке рисунка, переход к заметке по щелчку). Заметка с графом зависит от всего хранилища —
пересобирается при правке любой заметки. Вне приложения (`typst compile`)
`/_vault/` нет — будет ошибка чтения файла.

## Диаграммы по данным (`charts.typ`)

Когда данные — не функция, а измерения: время работы, размеры, доли.
Диапазоны, засечки «круглым» шагом, сетка и легенда считаются сами.

```typst
#fig(canvas(chart(
  (kind: "line", points: true, label: [перебор], data: ((1, 10), (2, 40), (3, 90))),
  (kind: "function", f: x => x * calc.log(x), from: 1, to: 5, label: [$n log n$]),
  width: 5.2, height: 3.2, labels: ([$n$], [мс]), legend: "inside",
)), [Что показывает диаграмма])
```

Виды рядов (`kind`): `"line"` (`points: true`, `dashed: true`), `"points"`, `"steps"`
(функция распределения, ступенчатые оценки), `"bars"` (данные —
`((подпись, значение), …)`), `"function"` (`f`, `from`, `to`).
Прочее: `x`, `y` (диапазоны, по умолчанию по данным), `ticks-x`, `ticks-y`,
`format-x`, `format-y`, `gridlines`, `legend` (`"right"`, `"inside"`, `none`).

Цвета задаются именами `"line"`, `"second"`, `"third"`, `"accent"` или типом `color`.
Имена превращаются в цвета текущей темы, поэтому один и тот же рисунок работает в любой теме.

**Оси:** y смотрит вверх во всех помощниках, кроме `matrix-cells` и `array-cells` (там
строки идут сверху вниз). **3D:** x вправо, z вверх, y уходит влево-вверх,
«от нас».

Внутри `import cetz.draw: *` имена `line`, `rect`, `content`, `fill`, `stroke`,
`anchor`, `mark` заняты функциями cetz — не называй так свои переменные.

## Математика (`math.typ`)

- `tg ctg arctg arcctg sh ch th cth rot grad const` — операторы в русской традиции.
- `dc("0,5")` — десятичная дробь с запятой. **Не** `$0,5$`: typst напечатает «0, 5».
- `dd(x)` — дифференциал.
- `defeq` — «равно по определению» ($:=$).

python3 baluk/lint.py data/vault      # сырые запятые в формулах, {,}, smallcaps

## Устройство библиотеки

Точка входа — `lib.typ`: он реэкспортирует публичные имена модулей, и
только они — интерфейс библиотеки (их список сверяет снимок
`tests/snapshots/baluk-api.txt`, тест `crates/notes-core/tests/library.rs`:
пропавшее или переименованное имя — падение теста, новое имя без
описания в этом README — тоже). Имена с `_` — служебные, их можно менять.

Большие модули разложены по темам в подкаталоги, файл верхнего уровня
собирает их вместе (`figures.typ`, `plots.typ`) — импорт `"figures.typ": …`
работает как раньше.

**Две ветки блока.** В HTML и в PDF у блока разная вёрстка, поэтому каждый
пишется так:

```typst
#let lead(body) = context {
  if is-web() { return elem("div", "k-lead", body) }   // HTML: разметка с классом
  …                                                    // PDF: вёрстка страницы
}
```

Общий помощник вида `web-or(html, pdf)` не заведён: ветки почти всегда
считают разное (HTML-ветке не нужны размеры и цвета PDF-ветки), а помощник
заставил бы оборачивать обе в функции — длиннее, чем `if is-web() { return … }`.
Страховки для чужой вёрстки (`grid`, `stack`, `place`, `align`, `h`, `v`)
стоят только в HTML-ветке шаблона (`_web-template`) и всё равно проверяют
`is-web()`: внутри `html.frame` вёрстка снова постраничная.
